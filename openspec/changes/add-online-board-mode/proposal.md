## Why

现在这套工具只做「线下辅助」（模式一）：实体棋盘、实体骰子、实体卡牌照常线下玩，手机只负责识别卡面与记账。凑不齐一桌人、或人不在同一个房间时，这局就开不起来——而规则引擎、194 张卡库、房间/事件溯源模型早已按「不堵死模式二」的约束建好（design/01 §模式二、design/03 §规则引擎为纯 IO 无关模块、design/06 §`raw` 逐字转录就是为纯线上渲染卡面准备的）。

缺的只有三样：**棋盘上的位置**、**服务端的骰子与牌堆**、**一块能让人愿意盯着看的棋盘**。这个 change 把这三样补齐，让一局游戏可以完全在网页里跑完，并且看上去、玩上去像一款正经做过的游戏，而不是一张会算账的表格。

## What Changes

### 房间模式（两种模式并存，建房时选）

- 建房时选「线下辅助」或「纯线上」，房间创建后不可更改；两种模式共用同一套引擎、卡库、记账、报表、日志、破产、快车道与胜负判定。
- 线下辅助模式的行为**一个字都不改**（M0–M4 的手动声明格子、选卡、OCR 全部原样保留）。纯线上模式禁用手动选卡与 OCR 入口，改由服务端发牌。
- 纯线上模式下，「我停在哪种格子」不再由玩家声明，由掷骰结果推导。

### 棋盘与移动（新）

- 玩家在内圈/快车道上有明确位置；开局所有人从「开始」箭头出发（位置 0 = 起点标记本身，不是第 1 格）。
- 掷骰由服务端摇（复用已有的 `_dice_rng` 与「点数写进事件流、可重放、不可重掷」的做法）。粒数**按赛道分开**：老鼠赛跑 1 粒，慈善生效的 3 轮内可选 1 或 2 粒（P.4）；快车道 2 粒，捐过款后永久可选 1、2 或 3 粒（P.6）。
- **回合顺序也归服务端**：说明书 P.2 是每人掷骰比大小，纯线上模式下由服务端替全员摇、按点数排，房主不再手排（手排本身是一次「声明线下发生了什么」）。
- 移动过程中**经过**的现金流量日/银行结算日逐格结算（说明书「停在或经过」语义），落点格子自动派发到既有引擎动作：机会格 → 玩家选大生意/小生意 → 发牌；市场风云/额外支出 → 直接发牌；慈善/孩子/失业/税务审计/离婚/官司 → 触发对应内建动作；梦想格/绿格 → 快车道既有面板。
- 内圈 24 格序列（design/05 §1 已存档，右列顺序标了 ⚠️ 待核）与快车道环形序列（design/05 尚未记录顺序，**本 change 的数据前置项**）落地为权威 JSON。

### 牌堆（新）

- 服务端持有每副牌的牌堆与弃牌堆：洗牌 → 逐张发 → 用完洗回。重复卡按实际张数入堆（CLAUDE.md 已定案：重复卡是真实牌堆构成，直接决定抽牌概率）。
- 洗牌顺序进事件流，状态仍等于 `reduce(初始, 事件流)`，重放与撤销行为不变。**但牌序绝不出房间边界**——事件 payload 有三条对客户端敞开的通道（房间状态、WS 广播的 `lastEvents`、日志接口），三处一起脱敏。
- 纯线上模式下 `DRAW_CARD` 不再由客户端指定 `card_id`；**「本人当回合更正」也一并关掉**——那是为线下认错实体卡准备的，纯线上退回牌堆顶再抽必然是同一张，只会让人困惑。撤销一律走房主。

### 职业卡改为系统随机发，梦想仍手动选

- **职业**：说明书 P.2 简明步骤 4 写的是「每位玩家**抽**一张职业卡」，不是挑一张。12 张卡工资从 $1,600 到 $13,200 相差 8 倍，让玩家自选等于开局就把平衡拆了。纯线上模式**保持现在的时机与位置不变**（房间准备页，玩家自己触发），只把「从列表里挑一张」换成「系统随机发一张」，且**抽过不能重抽**。线下辅助模式照旧——那边挑的动作是**录入你摸到的实体卡**（FR-5 原文），语义正确，一个字不改。
- **梦想**：说明书步骤 9 写的是「在快车道上**选择**您的梦想」，两种模式都是玩家手动挑，引擎的 `SELECT_DREAM` 一个字不改。纯线上模式下只改呈现——在准备页打开快车道棋盘点粉格选，选中即在该格插一枚自己颜色的圆点，那枚圆点就是实体游戏里放上去的奶酪。

### 呈现（呈现层定稿见 design/09-纯线上版UX设计.md v0.1）

- **纯线上另起一套页面骨架**：HUD（银行储蓄/月现金流 + 目标进度 + 轮次与本轮行动顺序）→ 棋盘主视图 → 底部三档抽屉（peek 128px / half 46dvh / full 88dvh）。**取消常驻标签栏**——棋盘要占满、抽屉要能拉到 88%，两者都跟一条 56px 的 tabbar 抢位置；报表/总览/日志收进棋盘右上角悬浮的「📋 账本」（full 档抽屉 + 分段控件），说明书入口是第二个悬浮按钮。线下辅助模式的四标签页一屏不动。
- **棋盘是一只 24 格放射轮盘，不是方格阵列**：老鼠赛跑就是仓鼠轮，圆形是这个游戏的字面意思，实体棋盘内圈本来也是这个样子。板底走 `--panel`/`--panel2`（不引入实体那块紫），所以进快车道换金箔肤时棋盘自己会跟着变金。快车道是同一只轮盘，格子多一倍、环收窄一半。棋子、当前玩家高亮、所有人的位置全员可见。
- **骰盘坐在轮心**：我的回合是可点的大骰子，别人的回合是只读点数。老鼠赛跑 1 粒、快车道 2 粒、慈善生效时玩家自选 1–3 粒（粒数选择器替换轮心的状态提示行，不弹层、不叠高度）。
- 掷骰、走格、过站结算、发牌、翻牌做成有节奏的演出序列（9 拍、单次约 3.2s），而不是状态瞬间跳变；**每一拍都能被一次点击跳过**——跳过是终止到终态，不是加速。全屏发牌翻牌全员同步播放（说明书要求把卡「大声读出来」）。关键时刻（进快车道、获胜、破产）已有的过场屏接上棋盘。
- 视觉沿用既有暖光纸感设计语言与阶段换肤（老鼠赛跑墨绿 / 快车道金箔），**零新增视觉 token**——新增的只有轮盘、棋子、骰子、牌背四个物件，材质规则仍是既有那三条（纸片底 `--panel`、暖色发丝线 `--line`、`--shadow-sm` 投影）。「大厂感」落在材质光影、动效节奏、反馈层级上。
- 回合三步在纯线上模式下变成：① 掷骰 → ② 处理落点 → ③ 结束回合。任何时刻只强调当前该做的那一步（design/03 §03 既定原则）。经过银行结算日在走格动画里作为一个「过站」节拍自动结算，不占一步，也不再需要线下那个「本回合没经过」的出口按钮——这是纯线上相对线下**唯一的流程简化**。第 ② 步能不能跳过按格子类型定：机会格必须抽一张（说明书规定），慈善格与快车道绿粉格本来就可做可不做，未决也能直接结束回合。

### 不做（Non-goals）

- 不做 AI/托管玩家，不做异步长局与离线通知——只做真人同房实时对局。
- 不改任何既有规则语义：公式、破产判定、快车道启动资金、卡牌效果全部不动。
- 不动卡库 `data`/`raw` 字段，不加新 subtype。
- 不改线下辅助模式的任何流程。
- **不做音效**（design/09 §11）：留到棋盘与动效落地之后单独一轮，否则会在动画节拍还在调的时候，就把音画对不上的问题固化下来。

## Capabilities

### New Capabilities

- `online-mode`: 房间的对局模式（线下辅助 / 纯线上）——建房时选定、不可更改、全员可见；两种模式下哪些动作可用、哪些入口关闭（含职业随机发、回合顺序服务端排、本人更正关闭）。
- `board-movement`: 棋子位置、服务端掷骰、移动与「经过」结算、落点到引擎动作的派发；内圈与快车道两套轨道。
- `card-decks`: 服务端牌堆的洗牌 / 发牌 / 弃牌 / 洗回，以及它与事件溯源、撤销、重放的关系。
- `board-presentation`: 虚拟棋盘的呈现与回合操作流——棋盘布局、棋子与掷骰动效、发牌与翻牌序列、非我回合的观战视图、动效可跳过与降级。

## Impact

**数据（新增/补录）**
- `server/data/board/fast_track.json`：**48 格排布已补录并经房主对实物核实**（2026-08-08，design/05 §3.3），落成 `squares` 的 `{index, ref}`——`index` 即身份、`ref` 前缀即类型，不存逐格 `id`/`type`。
- `server/data/board/rat_race.json`：24 格序列升级为带 `{id, type}` 的结构化格子。**顺序已由房主对实物核实无误**（2026-08-08，design/05 §1 的 ⚠️ 可撤），所以这一步只加字段、不动顺序。
- `tools/validate_cards.py` 的 `check_fast_track_board()` 已落地（格数、index 连续、与企业/梦想清单双向对账）；内圈的类型计数校验随结构化一起补。

**服务端**
- `server/app/engine/models.py`：`RoomState` 加对局模式与牌堆状态；`PlayerState` 加棋盘位置。
- `server/app/engine/engine.py`：新增 `ROLL_DICE`、`CHOOSE_DEAL_SIZE` 两个动作与落点派发；`DRAW_CARD` 在纯线上模式下改由牌堆发牌；`START_GAME` 在纯线上模式下先摇骰排回合顺序。
- `server/app/rooms.py` / `server/app/main.py`：建房参数带模式，`/api/rooms` 与房间序列化下发模式、位置、牌堆余量；事件出口（`broadcast_state` 的 `lastEvents`、`log_rows()` 的 `payload`）加按类型脱敏；棋盘接口在既有的 `/api/board/fasttrack` 上扩出内圈序列。
- `server/app/store/db.py`：`room` 表加模式列（既有房间默认线下辅助）。
- OCR 相关（`server/app/recognize/`）：不动，纯线上模式下前端不调用。

**前端**
- 新增纯线上房间骨架：HUD + 棋盘 stage + 三档抽屉 + 悬浮账本/说明书入口。既有四标签页（含 `ActionTab`）**只服务线下辅助模式**，不改造、不复用。
- 新增棋盘视图（内联 SVG 放射轮盘）与棋子/骰子/牌背/发牌动效组件。
- 大厅建房增加模式选择；模式徽章在建房页/大厅列表/加入页/房间准备页四处复用；`CardPicker`、OCR 扫描入口在纯线上模式下隐藏。
- 新增 `stage.ts`：位置/骰子/发牌的事件驱动演出队列（与既有 `receipts.ts` 同一入口，都从 WS `state.lastEvents` 派生）。

**测试**
- 引擎新增移动/发牌/派发的用例；既有测试一条都不能挂、一条不能跳（线下辅助模式行为不变是硬约束），基准数以动工前实测为准。
- `npm run ui-smoke` 增加纯线上模式的完整一局。

**风险**
- ~~棋盘顺序录错~~ 两条轨道均已对实物核实通过（2026-08-08），这条风险已关闭；后续结构化时不得顺手调整顺序。
- 牌堆状态进 `RoomState` 后，`_revert`（房主撤销）必须能把发出去的牌退回原位，否则重放不一致。
- 牌序泄露：`DECKS_SHUFFLED` 是事件，而事件 payload 会经 WS 广播与日志接口下发——只堵 `serialize()` 不够，三个出口要一起脱敏。
- **撤销与棋子位置最容易做错**：棋子位置由掷骰事件决定，撤销一次**抽卡**不该动棋子；只有撤销**掷骰**才回退位置。UI 上棋子若跟着跳回去，玩家会以为骰子也白摇了。
