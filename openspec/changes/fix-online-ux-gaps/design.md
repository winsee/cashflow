## Context

动机见 [proposal.md](./proposal.md) — Why。这里只列影响技术选择的现状：

- 纯线上模式的骨架是**另起的一套**（`OnlineRoomView` + `components/board/*`），
  与线下的四标签页（`PlayView` + `ActionTab`）并行存在，靠房间模式分流。
  design/09 §1.1 有一条硬约束：**线下辅助模式的任何一屏、任何一句文案、任何一次点击路径都不变。**
- 银行/转账/破产三块工具目前**只长在** `ActionTab.vue` 里（约 60 行模板 + 6 个方法 + 4 个 ref），
  与它的 `toolsOpen` 折叠态、`bankCard` 滚动锚点、`gotoBank(need)` 预填逻辑缠在一起。
- 骰子现在是 `.die` + `.die.rolling`（平面方块整块 `rotateX/rotateY` 打转，面上显示 `?`）。
- `DealCurtain` 写死渲染 `GameCard`；职业卡是另一个组件 `ProfessionCard`。
- 梦想选择在纯线上走 `BoardView` 的 `pickable` 分支（点粉格），线下走 `SwipePicker` + 梦想卡。
- 已有 51 屏 `ui-smoke` 断言（线下 38 + 纯线上 13），是「线下不动」这条约束唯一的机械化兜底。

## Goals / Non-Goals

**Goals:**

- 让纯线上模式在任何状态下**都有一条能走的路**（这是死局的根因，不是某个按钮的样式问题）。
- 呈现层对齐 design/09 v0.2，且**不新增视觉 token**：能复用既有类与组件的地方一律复用。
- 两种模式共用同一份资金操作实现，避免同一句文案日后在两处漂移。

**Non-Goals:**

- 不改引擎、协议、事件流、卡库（proposal — What Changes C）。
- 不重构纯线上与线下的骨架关系：仍然是两套页面靠模式分流，不做「一套界面两种配置」。
- 不给职业卡/梦想加音效（design/09 §11 待定项 3，单独一轮）。

> 原本还有一条「不处理起点棋子压标签」。房主已于 2026-08-09 定案（起点在格子之外），
> 且它与 D5「名牌移出圆盘」互为前提——名牌不挪走，环外就没有棋子的位置——故并入本变更，
> 见 tasks 4.6 / 4.7。

## Decisions

### D1 · 资金三块抽成共用组件，线下也改用它

新建 `components/tools/{BankPanel,TransferPanel,BankruptcyPanel}.vue`，纯线上放进账本第四页，
**线下 `ActionTab` 的模板等价替换成同一组件**。

- *为什么不复制一份给纯线上*：银行的文案里有「千元整数倍，月息 10%」「清偿其他负债请到报表页」这类
  规则说明，破产面板里有清算后果说明。两份实现意味着同一句话有两个副本，改一处忘一处只是时间问题。
- *为什么敢动线下*：那条硬约束说的是**玩家看到的东西不变**，不是代码不许动。
  模板整体搬进组件、props 只传 `me`/`others`，渲染结果逐字相同；线下 38 屏 ui-smoke 是兜底。
- `gotoBank(need)` 的滚动锚点改为 ref 到组件根元素（`defineExpose({ root })`），
  折叠态 `toolsOpen` 仍留在 `ActionTab` 自己手里 —— 那是线下独有的交互，不进组件。
- 备选方案（否决）：把三块做成 `ActionTab` 的 slot 供纯线上复用 —— 纯线上根本不渲染 `ActionTab`，
  为了取三块内容去挂载整个线下待办页是本末倒置。

### D2 · 资金操作进账本第四页，不加第三个悬浮按钮

账本的分段控件从 报表/总览/日志 变成 **报表/总览/日志/更多**。

- *为什么不在棋盘右上角加第三个悬浮钮*：那里已经有两个（账本、说明书），第三个开始像工具栏；
  而且这三块与报表/总览/日志同属「随时可查、随时可用」，不是本回合待办 —— 它们本就该在同一层。
- *为什么不进 `.drawer-cta`*：CTA 是「此刻该做的事」，贷款不是。

### D3 · 「结束回合」用独立的一行，而不是挤进同一行

`.drawer-cta` 改为纵向两行：上行卡片决策（各 `grow`），下行「结束回合」（可选卡时 ghost、无卡时主按钮）。

- *为什么不合并成「放弃并结束回合」一个按钮*：会丢掉一条 `CARD_PASSED` 事件，
  日志与撤销的粒度跟着变粗；而且「不买」与「结束回合」在规则上确实是两步。
- *为什么不横排三个按钮*：375 屏宽横排三个按钮每个只剩 ~110px，「买入 $2,000」这种带金额的文案放不下。
- 两行只出现在 half 及以上档 —— 第 1 行有内容 ⇔ 有未结算卡 ⇔ 档位规则已把抽屉提到 half，
  peek 档（128px）永远只有一行，不为此加高 peek。

### D4 · 骰子做成真 3D 立方体

六面 `preserve-3d`，「点数 → cube 旋转」是一张六行表（对面之和为 7），一处定义。
摇动 = 多轴 `infinite` 翻滚 + 整颗轻浮起；落定 = 写 `transform` 转到那一面（0.42s）+ 外层回弹（0.46s）。

- *为什么不让平面骰的数字快速跳变*：**跳变的数字看着像结果**，而结果只能来自服务端，
  玩家会觉得刚才那个 4 是被改掉的。这与 design/09 §4.2「客户端不预演」是同一条约束的两面。
  立方体天生没有这个问题：滚动中看见的是各面掠过。
- *为什么摇动必须 `infinite`*：定长动画（摇 0.5s 然后揭晓）在网络慢时只能在最后一刻换点数。
- **「还没掷」保留平面 `?` 骰**：立方体总有一面朝前，而没有点数可显示时不该摆一颗看似有结果的骰子。
  这是两种呈现共存的唯一理由，写进 spec 以免日后被「统一成一种」优化掉。
- 多粒靠负 `animation-delay` + 略不同周期 + 落定圈数不同来错开；同步转会看成一个整体在晃。

### D5 · 名牌移出圆盘，而不是在圆内挪位置

`.wheel-name` 去掉 `position:absolute; bottom:5%`，改为棋盘之上的静态一行，`compact` 时隐藏。

- *为什么不放圆内顶部*（设计稿 v0.1 的字面写法）：圆盘顶部净空只有 `V/2 − R1 = 26px`，
  还要留给起点三角与「开始」二字 —— 这正是当初实现挪到板底的原因，挪回去只会换个地方打架。
- 留下一条判据写进 spec：**圆盘内部只画棋盘本身**（格子、棋子、起点标记、轮心）。

### D6 · 职业卡揭牌复用 `DealCurtain`，靠插槽而不是分支

`DealCurtain` 加一个默认插槽（不传则照旧渲染 `GameCard`），职业卡场景传 `ProfessionCard`。

- *为什么不新写一个 `ProfessionReveal`*：翻牌的 3D 结构、牌背材质、帘幕基座都在 `DealCurtain` 里，
  复制一份就有了两处 `backface-visibility` 要一起调。
- *为什么不在 `DealCurtain` 里按 `deck === 'PROFESSION'` 分支*：卡面组件的选择是调用方的知识，
  不该让发牌组件认识职业卡。
- 重连不重播沿用既有判据（`me.professionId` 已有值 → 直接显示翻开态），与 §5.2 同一条。

### D7 · 梦想退回 `SwipePicker`，`pickable` 直接删掉

纯线上第 2 步改为与线下同一段模板；`BoardView` 的 `pickable` prop 与 `tap()` 里的 guard 一并移除。

- *为什么不保留两种选法*：多一个入口就多一份「哪个是权威」的疑问，而棋盘那条路本身信息更少
  （格面不写字，得戳一下才知道戳到了什么）。
- 保留棋盘作只读公示（已认领梦想插色点）——那是实体游戏里那块奶酪，信息价值真实存在。

## Risks / Trade-offs

- **动线下代码可能破坏那条硬约束** → 三块组件只做模板搬迁，不改结构与文案；
  改完先跑 `npm run ui-smoke` 比对线下 38 屏，逐屏确认无差异后才继续往下做。
  这一步放在任务序列的最前面（见 tasks.md 阶段 1），出问题时回滚面最小。
- **3D 立方体在小尺寸下可能糊或穿面** → 尺寸只有一个入口 `--d`，透视按 `--d` 比例算；
  32px（排序列表）与 58px（轮心）两个极端都要真机看一眼。`.face` 不用
  `backface-visibility:hidden`（立方体需要看到各面）。
- **`?` 骰与 3D 骰共存被后人当成不一致而"优化"** → 已写进 spec 的场景（别人还没掷时不摆点数），
  并在代码注释里写明理由。
- **两行 CTA 在 half 档挤掉卡面滚动区** → CTA 仍是 `position: sticky` 钉底，卡面区照旧可滚；
  half 档 46dvh 减去两行按钮（~96px）后仍有 ~250px 给卡面，`GameCard` 的 compact 态放得下。
- **账本第四页让分段控件变四个** → 375 屏宽下四个分段各 ~85px，「报表/总览/日志/更多」都是两字，装得下。

## Migration Plan

无数据迁移、无协议变更，纯前端呈现层，随镜像一起发布即可。落地顺序按风险从高到低排（详见 tasks.md）：
先做 D1 的组件抽取并用 ui-smoke 锁住线下不变，再补纯线上的死局出口（D2/D3 + 破产面板），
最后做纯视觉的几项（D4/D5/D6/D7）——前两段修的是"走不下去"，后一段修的是"不好看"，
万一时间不够，砍后面不砍前面。
