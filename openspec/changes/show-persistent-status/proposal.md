## Why

《现金流》里有一批**跨回合持续**的玩家状态：失业带来的停赛 2 轮、破产复活后的停赛 3 轮、
慈善捐款后的 3 轮双骰权（快车道是永久 1–3 粒）、破产清算中、出局、mk-029 的 200 个月分期收款、
孩子数。它们决定「这个人接下来能做什么」，同桌据此判断牌局形势。

**数据早就下发了，缺的是呈现。** `rooms.py serialize()` 对所有人下发同一份状态
（`viewer_id` 形参从未被使用，不存在差异视图），`charityTurns` / `skipTurns` /
`inBankruptcy` / `childCount` / `fasttrack.charity_forever` / `installmentReceivables`
全在里面。可是界面上：

- **慈善对别人完全不可见** —— 只有本人在线下行动页、纯线上 peek 条看得到；
  快车道的永久慈善只在线下 `FasttrackPanel` 给本人一枚徽章。
- **停赛只在两处**露给别人（纯线上牌桌、总览页），而纯线上牌桌只在「非我回合」才渲染。
- **座次条**自称能读出「这一轮还剩几个人到我」，但它只有 now/done/out 三态 ——
  有人停赛时这句话就是错的，那个人根本不会轮到。
- 同一句话在四五处**各写一遍**，措辞与配色已经开始打架：停赛在线下行动页是红
  `.badge.out`、在总览页是灰 `.badge`。

还有一条只能靠呈现解决：`skip_turns` 是在 `_advance_turn()` 里静默递减并跳过的，
那段代码跑在 **apply / 重放**阶段，**发不出事件** —— 所以「谁被跳过了」没有事件可听，
只能由状态本身说出来。

## What Changes

**纯呈现层：`server/` 一个字都不改**，协议、事件流、卡库、引擎全部零改动。

**A. 一处派生，四处露出**

- 新增 `web/src/statuses.ts`：`playerStatuses(p)` 按优先级返回全部持续状态
  （出局 > 破产清算 > 停赛 > 慈善 > 快车道慈善 > 快车道 > 分期收款 > 孩子数），
  每条带 icon / label / detail / tone / major；`majorStatus(p)` 给只画得下一个记号的地方用。
  两条赛道的慈善**是两条**，不合并（老鼠赛跑 3 轮 1–2 粒 P.4；快车道永久 1–3 粒 P.6）。
  停赛**不写来源** —— 引擎只存 `skip_turns`，2 轮来自失业、3 轮来自破产复活，
  状态里没有这个信息，猜出来的来源迟早会错。
- 新增 `components/StatusChips.vue` 渲染徽章行（复用既有 `.badge` 三个修饰符，不新造颜色）。
- 露出点：**牌桌每一行**、**总览页每个人**（含次要状态）、**座次条角标**、**本人徽章**。

**B. 两处照抄的代码收成组件**

- `components/PlayerTableRow.vue`：线下 `ActionTab` 与纯线上 `OnlineRoomView` 的牌桌行
  本就逐行相同（design/09 §6 原话是「用既有那套，不新写」，当时是抄了一份），现在共用一份。
- `components/SeatStrip.vue`：`OnlineRoomView` 里 HUD 与 peek 条各写了一遍同一份座次条。
- 顺带删掉重复文案：牌桌的步骤文案里不再说「已出局 / 正在破产清算 / 停赛中」，
  那三句归徽章（同 v0.4 修掉的「轮心把停赛说了两遍」——一个位置只有一个主人）。

**C. 状态开始的那一刻给全员一条回执**

`receipts.ts` 新增 5 个 case，范式照抄既有的 `ENTERED_FASTTRACK`：有确定的 `player_id`
就用它排除当事人，不进 `SELF_ACTION` 那张 6 秒时间窗的表。

| 事件 | 谁收到 |
|---|---|
| `UNEMPLOYMENT_HIT` | 当事人（既有）+ **其他人**（新增） |
| `CHARITY_DONATED` / `FT_CHARITY_DONATED` | 只有其他人（捐款是自己点的） |
| `BANKRUPTCY_STARTED` | 只有其他人（当事人直接进清算面板） |
| `BANKRUPTCY_RESOLVED` | 只有其他人，按新快照分「走出破产 · 停赛 3 轮」/「出局了」 |

`buildReceipts` 因此多一个**可选**参数 `next`（这批事件之后的快照）：破产的结局是在服务端
apply 里算的，payload 里看不出来。读的仍是服务端给的结果，**客户端不重算规则**。

沿用 design/09 §4.3.1 的频次判据「回执只收低频重击」：别人生孩子、分期推进、
银行结算日/现金流量日一律不进 —— 回执要点「我知道了」才消失，每回合逼人点一次是骚扰。

## Non-goals

- 不给棋盘棋子加状态标记（棋子小且会叠放，房主定案不加）。
- 不改「牌桌什么时候出现」的既有条件与抽屉档位规则。
- 不为了凑一屏冒烟测试去伪造状态或改引擎语义。
