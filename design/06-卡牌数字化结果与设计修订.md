## 2. 最重要的一条修订：卡面原文必须入库

design/04 原文写的是"卡库只存数值字段与简短标题/关键词，不存整段卡面文案"。**此约束作废**，改为：

> **卡面原文逐字转录进 `raw` 字段，不得省略。** 理由：纯线上版（无实体卡）要靠 `raw` 渲染卡面；线下线上结合版里，卡面文案是玩家理解剧情、做决策的主要载体，只给数值会让游戏体感大幅下降。

`raw` 的结构（详见 schema）：

```jsonc
"raw": {
  "title":    "待售公寓——2室1厅",      // 卡面主标题
  "subtitle": "您的职业",               // 职业卡用
  "body":     ["段落1", "段落2"],       // 正文，按卡面分段
  "fields":   [{"label":"成本","value":"$40,000"}],  // 标签:值，保留 $ 与千分位原样
  "groups":   [{"name":"收入","rows":[...]}],        // 表格式卡面（职业卡）
  "notes":    ["（如果你有孩子的话）"]  // 括注、脚注、录入者标注
}
```

`data` 与 `raw` 是**双轨**：`data` 是引擎唯一取数来源（整数、无货币符），`raw` 是渲染与人工核对来源。两者由 `tools/validate_cards.py` 交叉校验。

## 3. 数据模型变更（新旧对照）

### 3.0 字段设计三原则（v3 定稿，2026-07-21）

全库字段做过一轮审计（`tools/audit_fields.py`）后按三条原则精简：

1. **能推出的不存**——冗余字段迟早会与真相不一致；
2. **一个字段只有一种语义**——一名多义是最容易埋 bug 的形态；
3. **通用规则不逐卡标注**——说明书里已是全局规则的，不做成卡片属性。

据此删掉的字段（共 237 处）：

| 删除 | 张数 | 依据 |
|---|---|---|
| `effects` | 194 | 审计显示每个 subtype 的 effects 完全一致、**无一张覆写过**，100% 可由 subtype 查表推出 |
| `loanAllowed` | 5 | 说明书 p6：「您可以向银行贷款，**除非您被宣布破产**」——贷款是通用规则，卡面那句只是提醒 |
| `costUnchanged` / `tradingLocked` | 各 4 | STOCK_EVENT 上恒为 true。「总成本不变」「此时不能交易」是并股/拆股的固有规则 |
| `unitCost` | 1 | 收藏品单价 = `cost ÷ quantity`，可推导 |

消歧义的重命名与拆分：

| 改动 | 原因 |
|---|---|
| 资产侧 `priceBasis` → `resaleBasis` | 与求购卡的 `priceBasis` 同名不同义：前者是「本资产怎么估值」，后者是「求购方怎么算价」 |
| `condition` → `payerCondition` / `assetCondition` | 原字段混了两种判定对象：`hasChildren` 判定**玩家**，`cashflowPositive` 判定**资产** |
| `appliesTo: ALL_OWNERS` → `ALL` | 与 `buyerScope` 的值域统一 |
| `LOSS_EVENT` 并入 `EXPENSE_EVENT` | 字段形状相同，schema 本就同分支处理，两个名字无收益（subtype 由 18 → 17） |

补完整：

| 改动 | 张数 | 依据 |
|---|---|---|
| `roiPct` 改为必填 | +29 | 股票卡卡面印「投资收益率＝0%」，原先漏存，现补 0 |
| `incomeCategory` 扩为四类并补全 | +51 | 说明书 p7 记录卡收入栏为 工资/**利息**/**股利**/**房地产**/**企业投资**，资产的现金流必须知道记入哪一行 |

各分支 `data` 已加 `additionalProperties: false`，写错字段名会在校验时直接报错。

### 3.1 subtype 由 13 个扩到 17 个

新增 5 个，全部因为原设计覆盖不到实体卡里真实存在的机制：

| 新 subtype | 触发卡 | 原设计为何不够 |
|---|---|---|
| `DICE_GAMBLE` | sd-013 嫂子借钱 | 付 \$5,000 后**掷一粒骰子，>3 得 \$10,000，否则血本无归**。原设计没有任何随机结算机制 |
| `COLLECTIBLE` | sd-036 稀有金币、sd-053 克鲁格金币10枚 | 按**件数**持有、无现金流、靠市场卡按枚定价变现 |
| `PREMIUM_OFFER` | mk-006 利率下降 | 以「**原价 + \$50,000**」成交。原有 `BUYER_OFFER`（定价）与 `MULTIPLE_OFFER`（倍数）都表达不了 |
| `INSTALLMENT_SALE` | mk-029 妹夫买房 | 无首付、四年付清 \$100,000，**卖方月现金流反而 −\$500** 直到收齐 |
| `CASHFLOW_MODIFIER` | mk-008 (+\$250)、mk-009 (+\$400) | 不转移资产，只改所有「自建企业」持有者的月现金流。原 `ECONOMY_EVENT` 仅有没收/改支出两种 kind |

### 3.2 求购卡必须区分计价基准

原设计只有 `pricePerUnit` 一个字段。实体卡里存在**三种互不相同的计价方式**，混淆会直接算错钱：

| priceBasis | 含义 | 卡例 |
|---|---|---|
| `PER_UNIT` | 每**套** | mk-018「公寓房不论大小，每套 \$25,000」 |
| `PER_ROOM` | 每**间房**（按 2室/4室/8室 的房间数乘） | mk-020「2室、4室、8室任意户型，每间房 \$40,000」 |
| `PER_PIECE` | 每**枚/盎司** | mk-007 克鲁格金币 \$600/盎司、mk-010 金币 \$5,000/枚 |

同一张 8室公寓，遇到 PER_UNIT \$25,000 只值 2.5 万，遇到 PER_ROOM \$40,000 值 32 万——**差 13 倍**。因此资产必须记 `rooms`（房间数）与 `units`（套数）两个规格字段，求购卡才能正确结算。

另新增：
- `minUnits`：mk-015「求购 **12 套以上**的公寓房」——不满 12 套不能卖；
- `condition`：mk-032 求购旅馆要求「**且能盈利**」（cashflowPositive）。

### 3.3 股票卡必须区分「谁能买」

原设计完全没有这个字段，但它决定交易窗口对谁开放：

| buyerScope | 卡面措辞 | 卡数 |
|---|---|---|
| `DRAWER_ONLY` | 「只有你才能按此价格购买」「只有你一个买主」 | 大多数股票/基金卡 |
| `ALL` | 「每个人都能以此价格**购买或出售**」 | 优先股 2BIG（sd-001/011）、银行存单 CD（sd-029/050） |

**卖出侧一律是所有人可卖**（「每个人都可以按此价格出售」），这点原设计是对的。

### 3.4 收入要按记录卡的四个栏目分类

说明书 p7 的记录卡收入栏是：**工资 / 利息 / 股利 / 房地产 / 企业投资**，且明确
`非工资收入 = 利息 + 股利 + 房地产 + 企业现金流`。资产产生的现金流必须知道记入哪一行，
否则「非工资收入 > 总支出」这个胜利条件就算不准。

`incomeCategory` 值域即对应这四行：

| 值 | 记入记录卡 | 卡例 |
|---|---|---|
| `INTEREST` | 利息 | 银行存单 CD（sd-029 本金 \$5,000 收益率 4.8%；sd-050 \$4,000 / 6%） |
| `DIVIDEND` | 股利 | 优先股 2BIG，\$10/月/股 |
| `REAL_ESTATE` | 房地产 | 全部 REALESTATE 资产（41 张有现金流的） |
| `BUSINESS` | 企业投资 | 全部 BUSINESS 资产（10 张有现金流的） |

现金流为 0 的资产（土地、荒地、金币、兼职办公司）不填此字段——它们不进收入栏，只进资产栏。

原设计只有 `dividendPerShare` 单字段，会把利息错记到股利栏，且房地产/企业的归属完全没表达。

### 3.5 支出事件的两个限定词

`bd-003 下水管破裂`、`bd-038 房产受到房客破坏`、`sd-007 承租人损坏财产` 都带限定：

- `chargeOnce: true`——「如果你有**多套** 8 室公寓楼房，**只需支付一套**的修理费」。原设计的 `amountPerUnit` 语义会按套数累乘，**算错**；
- `appliesTo: "DRAWER_ONLY"`——「**只有抽到本卡的人**才需要支付」，不波及其他玩家。

卡面还写着「可以通过条款取得银行贷款」，但**这不是卡片属性**——说明书 p6 规定贷款随时可用（除非破产），所以不设字段（见 §3.0）。

### 3.6 其余新增字段

| 字段 | 用途 | 卡例 |
|---|---|---|
| `cashflow` 可为负 | 买了反而每月扣钱 | bd-008、bd-041、sd-045、sd-051（均 −\$100） |
| `downPayment: 0` | 零首付 | sd-031、sd-051（成本=抵押=\$50,000） |
| `roiPct: null` | 卡面印「投资收益率未知」 | sd-031、sd-051 |
| `priceIndeterminate` | **卡面未给出转售参考价**——印「售价不能确定」「可能在将来以某个价格卖掉」或「目前没有其他买主」。**不表示不可转售**（见 §6.3） | bd-042、bd-004、bd-010、bd-016、bd-023、sd-017、sd-018、sd-049、sd-053 |
| `priceBasis: CASHFLOW_MULTIPLE` + `priceMultipleRange` | 「售价可能为年月现金流量的 **12~25 倍**」 | bd-037 洗车店 |
| `amountPerChild` | 「为**每个**小孩花费 \$50」 | dd-021 |
| `quantity` / `unitCost` | 一次买入 10 枚金币，每枚 \$300 | sd-053 |
| `duplicateOf` | 同内容重复卡，牌堆构成需要 | 见 §5 |

## 4. 规则引擎（design/02）需要增补的内容

### 4.0 subtype → effects 映射表（替代已删除的 effects 字段）

`effects` 字段已删除，引擎按下表由 subtype 推出：

| subtype | op 序列 |
|---|---|
| REALESTATE / BUSINESS / COLLECTIBLE | `OFFER_BUY_ASSET` → `OFFER_RESELL` |
| DICE_GAMBLE | `OFFER_BUY_ASSET` → `ROLL_DICE_PAYOUT` |
| STOCK_OFFER | `STOCK_TRADE_WINDOW` |
| STOCK_EVENT | `ADJUST_SHARES`（总成本不变，事件期间交易窗口关闭） |
| EXPENSE_EVENT / CASH | `FORCE_PAY` |
| BUYER_OFFER / MULTIPLE_OFFER / PREMIUM_OFFER | `MARKET_SELL_OFFER` |
| INSTALLMENT_SALE | `MARKET_SELL_OFFER` → `SCHEDULE_INSTALLMENT` |
| CASHFLOW_MODIFIER | `MODIFY_CASHFLOW` |
| ECONOMY_EVENT | `FORCED_SURRENDER` |
| CREDIT_OPTION | `OPTIONAL_CREDIT` |
| INSTALLMENT | `ADD_INSTALLMENT` |
| PROFESSION | `APPLY_PROFESSION` |

真出现需要覆写的特殊卡时，再引入 `effectsOverride` 字段——**不要**恢复逐卡存 `effects`。

### 4.1 新增 3 个 op

| op | 语义 | 备注 |
|---|---|---|
| `ROLL_DICE_PAYOUT` | 扣款 → 掷骰 → 按条件判定赔付 | 服务端掷骰并记入事件流，客户端只展示；结果不可重掷 |
| `MODIFY_CASHFLOW` | 给所有符合条件的持有者增减月现金流 | 作用于**已持有的资产条目**，不是玩家总账 |
| `SCHEDULE_INSTALLMENT` | 登记一笔跨 N 个月的分期收款，到期自动结算 | 仅 mk-029：−\$500/月 × 200 个月，期满恢复现金流并入账 \$100,000。需要按"月"（回合）推进的计数器，与慈善 3 轮/停赛 2–3 轮共用回合指针机制 |

### 4.2 必须补的回归测试（在 design/02 §13 测试清单上追加）

1. **按间计价**：持有 8 室公寓，遇 mk-020（PER_ROOM \$40,000）应结算 \$320,000，而非 \$40,000；
2. **套数门槛**：持有 8 套公寓楼遇 mk-015（minUnits=12）→ 不可出售；持有 24 套 → 可售 \$720,000；
3. **只付一套**：持有 3 套 8 室公寓遇 bd-003 → 只扣 \$2,000；
4. **抽卡人限定**：bd-038 只扣抽卡人，其他持有房产的玩家不动账；
5. **买家范围**：非抽卡人尝试买入 DRAWER_ONLY 股票 → 拒绝；买入 2BIG/CD → 允许；
6. **利息入账**：买入 CD 后「利息」栏 +\$20，「股利」栏不变；
7. **负现金流资产**：买入 bd-041 后月现金流应**减少** \$100；
8. **零首付**：买入 sd-031 现金不变、负债 +\$50,000、月现金流 +\$100；
9. **并股/拆股**：股数减半/翻倍而**总成本不变**，且事件期间交易窗口关闭；
10. **骰子赌局**：sd-013 固定随机种子下，点数 4/5/6 得 \$10,000，1/2/3 无收入；
11. **企业细分匹配**：持有 sd-018（小型机械公司）遇 mk-033（求购软件公司）→ **不可**出售；遇 mk-025 → 可售 \$50,000；遇 mk-008 → 月现金流 +\$250；
12. **土地合并**：持有 sd-017（\$5,000 买入）遇 mk-026 → 可售 \$150,000；
13. **分期收款**：mk-029 成交后第 1~199 月现金流 −\$500 且未入账；第 200 月现金流恢复且现金 +\$100,000；中途破产/退出时该笔挂账的处理需明确（建议：清算时按已扣月数比例折算）。

## 6. 裁决点（房主 2026-07-21 全部定案）

### 6.1 ✅ 已定案：sd-017 就是 mk-026 要买的标的

- sd-017：「**10 亩**的荒地，有**小溪**流过……像公园一样」，\$5,000 买入；
- mk-026：建筑商求购「带**河流**的 **10 英亩**土地」，\$150,000。

译名不统一（亩/英亩、小溪/河流），**判定为同一标的**，两边 `assetType` 统一为 `10英亩土地（带河流）`。这是全库唯一一条 30 倍收益的"荒地暴富"路径；若不合并，sd-017 会变成永远无法变现的死资产。

### 6.2 ✅ 已定案：企业按细分类型匹配，不是所有公司都通用

求购卡**指名企业类型**，因此资产要存两级标签：

| 买入卡 | assetType | businessKind | 谁能买 |
|---|---|---|---|
| **sd-018** 兼职办公司（小型机械产品）\$3,000 | 自建企业 | 小型机械公司 | **mk-025** \$50,000 |
| **sd-049** 兼职办公司（游戏软件）\$5,000 | 自建企业 | 软件公司 | **mk-033** \$100,000 |
| 两张共有 | 自建企业 | — | **mk-008** +\$250、**mk-009** +\$400 月现金流 |

`assetType` 供 mk-008/009 这类"泛指自建企业"的卡匹配，`businessKind` 供 mk-025/033 这类指名求购的卡匹配。schema 新增 `businessKind`（资产侧）与 `targetBusinessKind`（求购侧）。

### 6.3 ✅ 已定案：「目前没有其他买主」是剧情，不是规则

> ⚠️ **这是本次数字化过程中最严重的一次误读，务必看清。**

初版把卡面的「目前没有其他买主」当成机制，建了个 `noBuyer` 字段，并据此推出"这 4 张自动化企业买了就再也卖不掉"。**这是错的。**

这句话是**卡面剧情文案**，在解释这笔生意为什么划算——没人跟你抢，你可以从容拿下。看它在卡面上出现的位置就很清楚，它占的正是别的卡印售价区间的那一行：

| 卡面写法 | 真实含义 |
|---|---|
| 「投资收益率为48%，**售价在\$100,000~\$140,000之间**」 | 给出了转售参考价 |
| 「投资收益率为96%，**目前没有其他买主**」 | **未给出转售参考价**（剧情上解释为没人抢） |

因此它唯一的机制含义是「卡面没印转售参考价」，与 bd-042 土地的「售价不能确定」等价，统一用 `priceIndeterminate` 表达。**`noBuyer` 字段已删除。**

**连带修正**：曾以此为由把 bd-023（4家投币式洗车店）排除在 mk-035 之外，该理由不成立，已恢复匹配（见 §6.5）。

**真正没有市场买家的只剩 1 张**：bd-031 比萨饼特许专卖店（\$500,000 / +\$5,000/月）——它卡面**有**售价区间 \$520,000~\$800,000，只是全套 42 张市场卡里恰好没有求购「特许专卖店」的。这属于**牌组构成**的事实，不是规则限制，玩家之间仍可私下转让。

### 6.4 ✅ 已定案：mk-029 分期收款按 200 个月结算

卡面「四年内」是剧情文案，**机制以数值为准**：\$100,000 ÷ \$500 = **200 个月**。

结算方式（`onCompletion: RESTORE_CASHFLOW_AND_PAY`）：
1. 成交时移交房产、月现金流 **−\$500**，不收首付；
2. 此后每月扣减持续计数；
3. 满 200 个月时：月现金流恢复 **+\$500**，同时一次性入账 **\$100,000**。

已移除 `needsHostAdjudication`，改为引擎自动结算，新增 `durationMonths: 200`。

### 6.5 ✅ 已定案：mk-035 收购一切「汽车清洗公司」

全库检索确认洗车相关卡仅 3 张（mk-035 / bd-023 / bd-037），无转录遗漏。两张买入卡**都**可被 mk-035 收购：

| 卡 | assetType | businessKind | 成本 | 月现金流 |
|---|---|---|---|---|
| **bd-037** 洗车店 | 洗车店 | 汽车清洗公司 | \$350,000 | +\$1,500 |
| **bd-023** 4家投币式洗车店 | 自动化企业 | 汽车清洗公司 | \$125,000 | +\$1,800 |

两者 `assetType` 不同，所以 **mk-035 不写 `targetAssetType`，只写 `targetBusinessKind`**，按企业类型跨类匹配。schema 已放宽为 `targetAssetType` 与 `targetBusinessKind` 二选一必填。

**bd-023 的整体性**：\$125,000 是 4 家洗车店作为**一个资产整体**的成本，**不可**拆成 4 个资产单位按 PER_UNIT 重复结算。

**一条数值佐证**：bd-037 卡面写「售价可能为年月现金流量的 12~25 倍」，月现金流 \$1,500 → \$18,000~\$37,500，mk-035 报价 \$25,000 正落其中。已加入自动校验（定价求购的报价与标的卡面售价区间交叉比对，越界告警）。

> **两条被推翻的错误推理**（引擎实现时不要重蹈）：
> 1. ~~"卖 \$25,000 要先还 \$300,000 抵押、净亏 27.5 万，所以不是同一标的"~~ ——
>    **出售始终是可选的**，报价低玩家拒绝即可，"卖了亏"不构成匹配矛盾。
> 2. ~~"bd-023 卡面写了没有其他买主，所以不参与求购"~~ —— 那是剧情，见 §6.3。
>
> **对引擎的硬性要求**：`MARKET_SELL_OFFER` 一律只推送要约、绝不自动成交，
> **也不得因"卖了会亏"而过滤或隐藏要约**——玩家完全可能为了套现渡过破产危机而主动贱卖。

## 7. 资产类型受控词表

市场卡靠 `targetAssetType` 精确匹配玩家资产，**字符串必须来自同一词表**，否则卖不出去。当前词表：

- **住宅**：`3室2厅`、`2室1厅`
- **公寓（按间计价）**：`公寓` + `rooms: 2 | 4 | 8` ——**必须是同一个字符串**，卡面的"2室公寓/4室公寓/8室公寓"只体现在 `title` 里
- **公寓楼（按套计价）**：`公寓楼` + `units: 12 | 24 | 60`
- **商业地产**：`购物商场`、`住宿和早餐旅馆`
- **土地**：`20英亩土地`、`10英亩土地（带河流）`（§6.1 已合并 sd-017）
- **企业**：`自建企业`（+ `businessKind: 小型机械公司 | 软件公司`）、`洗车店`（+ `businessKind: 汽车清洗公司`）、`自动化企业`（bd-023 带 `businessKind: 汽车清洗公司`）、`有限合伙`、`特许专卖店`

> `businessKind` 是**跨 assetType 的横切标签**：mk-035 只写 `targetBusinessKind`，就能同时命中 `洗车店`（bd-037）和 `自动化企业`（bd-023）名下的汽车清洗公司。求购卡 `targetAssetType` 与 `targetBusinessKind` 二选一必填。
- **收藏品**：`克鲁格金币`、`八里亚尔比索金币`（带 `quantity`）
- **证券**：`ON2U`、`MYT4U`、`OK4U`、`GRO4US`、`2BIG`、`CD`

> ⚠️ **踩过的坑**：初版把公寓拆成 `2室公寓/4室公寓/8室公寓` 三个类型，而 mk-020 等 **10 张**「求购公寓·每间房」的标的字符串是 `公寓`，字符串对不上 → 15 张公寓卡全部卖不掉。房间数必须放 `rooms` 字段而非揉进类型名。

**落地要求**：这份词表应在 M1 实现时提为 `server/data/schema/asset_types.json` 并被 schema 引用为 enum，杜绝错别字导致的匹配失败。`tools/validate_cards.py` 已加入双向交叉检查（求购标的必有买入卡、买入资产应有求购卡），此类错配会在 CI 里直接报错。

## 8. 对识别方案（design/04 §4）的影响

- **牌叠内候选规模确定**：小生意 56、大买卖 42、市场风云 42、额外支出 42，`deck_hint` 必传后搜索空间足够小；
- **股票卡是识别难点**：MYT4U 有 \$1/\$5/\$10/\$20/\$30/\$40 六种价位、版式几乎相同，**只有正文剧情句和今日价数字不同**。评分权重要向「今日价数字」倾斜，标题相似度会误导；
- **重复卡不必区分**：9 组重复卡内部完全等价，识别到组内任一张即可，Top-3 展示时按 `key` 去重；
- `ocr_keywords` 已按「标题 + 代码 + 显著金额 + 剧情特征词」录好（如 sd-028 的「市场恐慌」「股灾」），可直接用于 RapidFuzz 打分。

## 9. 人工核对流程

```powershell
python tools/crop_cards.py     # 生成裁剪图（首次或原图更新后）
python tools/build_review.py   # 生成 build/review/index.html
python tools/validate_cards.py # 改完 JSON 后必跑
```

打开 `build/review/index.html`：左边实体卡照片，右边上半是 `raw` 原文（按卡面版式还原，便于逐字比对）、下半是 `data` 结构化数值。逐张点「✓ 无误」或「✗ 有误 + 备注」，进度存在浏览器本地可分次做；全部过完点「导出结果」得到 `review-result.json`，据此回改 `server/data/cards/*.json` 后重跑校验脚本。

按牌叠筛选、隐藏已核对，194 张预计 60–90 分钟可完成一轮。
