# 纯线上版 UX/UI 设计稿

> 版本 v0.1 · 2026-08-05
> 配套变更：`openspec/changes/add-online-board-mode/`
> 权威范围：**呈现层与交互**。规则、公式、账目一律以 design/02 为准，本文一个字都不改它。
> 可视化稿：见本文 §10 屏幕清单（高保真 HTML 稿单独交付）。

## 0. 这份稿子解决什么

线下辅助模式的界面，本质是一张**会算账的记录卡**：玩家在实体棋盘上走完格子，回到手机上告诉 App
「我停在哪种格子」「我抽到哪张卡」。所以那套界面的主干是「引导式待办」——一次只问一件事。

纯线上模式没有实体棋盘可看。如果照搬那套待办流，玩家面对的就是一串没有上下文的问句：
不知道自己在哪、不知道别人在哪、不知道刚才那 6 步走过了什么。**棋盘不是装饰，它是这个模式里
唯一的空间上下文**。所以纯线上模式换一套信息架构：棋盘做主视图，操作收进底部抽屉。

同时，线下辅助模式的界面**一屏都不动**。两套架构靠房间模式分流，不做「一套界面两种配置」的折中——
折中的结果是两边都不好用。

## 1. 两种模式并存

### 1.1 模式的边界

| | 线下辅助 | 纯线上 |
|---|---|---|
| 棋盘 | 实体 | 屏幕（本稿主体） |
| 骰子 | 实体 | 服务端摇，全员同步播放 |
| 卡牌 | 实体 + 扫描/手选 | 服务端牌堆发牌 |
| 停留格 | 玩家声明 | 落点推导 |
| 银行结算日 | 玩家声明「经过几次」 | 走格时自动逐格结算 |
| 界面主干 | 四标签页 + 引导式待办 | 棋盘主视图 + 三档抽屉 |
| 规则 / 账目 / 报表 / 日志 / 破产 / 快车道判定 | ← 完全相同 → | |

**一条硬约束**：线下辅助模式的任何一屏、任何一句文案、任何一次点击路径都不变。本稿新增的所有
组件都挂在 `mode === 'ONLINE'` 分支下，不去改既有组件的默认行为。

### 1.2 分流点（四处）

1. **建房页**——两张模式卡二选一，沿用 `.bigbtn` / `.bigbtn.alt` 的一深一浅。选中态用 `.card.selected`。
   卡面写清「你需要准备什么」：线下辅助要「实体棋盘 + 骰子 + 卡牌」，纯线上「什么都不用，一台手机」。
2. **大厅房间列表**——每条房间带模式徽章，排在「第 N 轮 · X 人在线」之前。玩家在点进去之前就知道。
3. **加入房间页**——输入房间码后，确认卡上写明模式；纯线上房加一句「棋盘和牌都在屏幕里」。
4. **房间准备页**——模式徽章挂在房间码旁边，**带一把锁图标**，点击弹一句「模式在建房时选定，
   开局后不可更改」。这是规格里明写的约束（online-mode spec），UI 上要让它看起来就是不可改的，
   而不是一个看着能点、点了报错的控件。

### 1.3 模式徽章（一处定义，四处复用）

```
线下辅助   .badge            ⚄ 线下辅助      灰底暖线框，中性
纯线上     .badge.turn       ▣ 纯线上        主色浅底（--brand-soft）
```

徽章文字固定这四个字，不用「模式一 / 模式二」——那是文档里的编号，玩家不认。

## 2. 纯线上模式的信息架构

```
┌─────────────────────────────┐
│ 银行储蓄 $2,430   月现金流 +$1,150│
│ 离快车道 · 非工资 X / 总支出 Y  60%│  HUD 条，约 99px + 安全区，sticky
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬     │
│ ● 轮到你了 · 第 7 轮  我 明 林 赵 │  ← 轮次 + 一轮的行动顺序
├─────────────────────────────┤
│                             │
│         棋 盘 区             │  flex: 1
│      （24 格轮盘）            │  右上角悬浮：📋 账本 · 📖 说明书
│                             │
├─────────────────────────────┤
│ ▬▬  底部抽屉                 │  peek 128px / half 46dvh / full 88dvh
└─────────────────────────────┘
```

### 2.0 HUD 的最后一行：轮次与行动顺序

**和线下辅助模式的 `.hud-turn` 是同一条**——「● 轮到你了 · 第 7 轮」/「等待 阿明 行动 · 第 7 轮」，
断线时补一句「· 重连中…」。右端多一排**座次条**：

- 每人一枚 19px 的圆，按座位顺序排（就是一轮里的行动顺序，一局不变）；
- **当前行动者**实心 + 自己的色 + 一圈同色光环；**本轮已行动过的**淡到 40%；
  还没轮到的留浅底描边；出局的灰掉。
- 一眼能读出三件事：现在第几轮、轮到谁、这一轮还剩几个人到我。

> 这条加上去之后，**轮心就不再写轮次了**（见 §3.4）——同一个数没有理由在一屏里出现两次，
> 而且轮心在 half 档只有 100px 宽，「第 7 轮 · 阿明行动中」这种长度必然溢出。

### 2.1 为什么取消常驻标签栏

棋盘要占满，抽屉要能拉到 88%，两者都跟一条 56px 的常驻标签栏抢位置。所以纯线上模式里
**没有 tabbar**：报表 / 总览 / 日志三页收进「📋 账本」——点开就是 full 档抽屉，顶部三个分段控件切换。
它们是「随时可查」而不是「本回合待办」，本来就不该和棋盘平级。

说明书入口（`/manual`）保留为棋盘右上角第二个悬浮按钮，与线下模式 HUD 里那个入口等价。

### 2.2 三档抽屉

| 档位 | 高度 | 用途 | 棋盘 |
|---|---|---|---|
| **peek** | 128px | 一行状态 + 主 CTA（掷骰 / 结束回合 / 等待别人） | 完整可见 |
| **half** | 46dvh | 卡面与决策、落点选择、求购要约、股票交易 | 等比缩小到装得下，整块仍完整可见 |
| **full** | 88dvh | 破产清算、账本三页、快车道格子选择器 | 贴顶对齐，只留顶部一线 |

规则：

- **档位由内容决定**，不由用户记忆决定。掷骰 → peek；抽到卡 → half；破产清算 → full。
- 用户可以拖动覆盖当前档位，但**下一次系统事件会重新提档**——提档只升不降。别人抽的市场卡要我
  答复时，不能因为我刚把抽屉推下去就把这件事藏起来。
- 抽屉展开时棋盘**不加遮罩**（还要看别人的位置）。
- **棋盘缩的是自己的尺寸，不是 `transform: scale`**。stage 有 `overflow: hidden`，缩放 stage 会
  连同它的裁切框一起缩，棋盘照样被裁在原来的位置——白缩一场。实现上给棋盘一个 `--bw` 宽度变量，
  档位切换时改这个变量（`aspect-ratio` 保证比例），配 `transition: width` 出动效。
- **决策按钮钉在抽屉底**（`position: sticky`）。一张牌堆卡加上前后对比预览就超过 half 档的高度，
  内容必须能滚；但「买入 / 放弃」不能跟着滚出屏幕。按钮条上方压一道 `--panel` 渐变，
  滚动内容从它下面划过去。
- 把手条复用 `.sheet-grab`，拖拽手感与既有 `BaseModal` 一致。

### 2.3 抽屉与既有弹层的关系

既有的 `BaseModal`（求购要约、股票窗口、二次确认）**继续用**，压在抽屉之上（`--z-sheet` / `--z-confirm`）。
分工照旧、不新增规则：

- **我的待办** → 抽屉（页内聚焦，等价于线下模式的「页内聚焦卡」）
- **别人的动作波及到我** → `BaseModal` 底部弹层
- **二次确认** → `ConfirmDialog`

## 3. 棋盘

### 3.1 老鼠赛跑内圈：24 格放射轮盘

**实体棋盘的内圈是一只轮盘**——24 个扇形格子围着中心那只穿西装的老鼠，外面套两圈蓝青装饰环
（`docs/游戏棋盘.jfif`）。线上照这个来：

> **老鼠赛跑就是仓鼠轮，圆形是这个游戏的字面意思**：你在一只轮子里跑圈，跑不出去就一直跑。
> 画成方格阵列，等于把它最认得出的那样东西丢了。

几何（SVG viewBox 320×320，随板宽等比缩放）：

| | 值 |
|---|---|
| 格子外径 / 内径 | 134 / 94 |
| 中径（标签与棋子的基准） | 114 |
| 每格 | 15°，缝 1.5° |
| 弧长 × 径向宽 | 约 30 × 40px |
| 轮心可用直径 | 180px（放骰子与轮次） |

板宽 332px（375 屏宽减去 stage 的左右 padding），刚好铺满。

**标签一律水平不旋转**：切向排会把 3 点和 9 点方向的字竖过来，径向排会把左半圈的词序读反。
30×40 的格子里放两个 10px 的字绰绰有余，没有理由为了「精致」牺牲可读性。

格子顺序照 design/05 §1，自「开始」箭头顺时针：

```
① 机会    ② 额外支出  ③ 机会    ④ 慈善事业  ⑤ 机会    ⑥ 银行结算日
⑦ 机会    ⑧ 市场风云  ⑨ 机会    ⑩ 额外支出  ⑪ 机会    ⑫ 孩子
⑬ 机会    ⑭ 银行结算日 ⑮ 机会   ⑯ 市场风云  ⑰ 机会    ⑱ 额外支出
⑲ 机会    ⑳ 失业     ㉑ 机会    ㉒ 银行结算日 ㉓ 机会   ㉔ 市场风云
```

**机会格与事件格严格交替**——奇数格全是机会。这条性质对呈现有用：12 个机会格不写字（§3.2），
所以画出来就是「一圈色块与一圈标签相间」，不会出现两个空白格挨在一起的视觉断裂。

> ✅ 顺序已对实物核实（2026-08-08），design/05 §1 的 ⚠️ 已撤销。**渲染以
> `server/data/board/rat_race.json` 为准**，本稿的棋盘完全由该 JSON 驱动，格数与顺序变了不用改一行呈现代码。
> （本稿 v0.1 抄的是 design/05 v0.1 那版错开一位的序列，已随核对一并订正。）

### 3.2 格子的视觉：印刷品，不是色块阵列

格子颜色直接取既有的牌堆色变量——它们本来就是「取自实体棋盘的格子」：

| 格 | 变量 | 色 | 标签 |
|---|---|---|---|
| 机会 | `--deck-small` | `#8FBF3F` | **不写** |
| 银行结算日 | `--deck-payday` | `#E8913C` | 结算 |
| 市场风云 | `--deck-market` | `#4FA8C8` | 市场 |
| 额外支出 | `--deck-doodad` | `#B07FC0` | 支出 |
| 慈善事业 | `--deck-payday` | `#E8913C` | 慈善 |
| 孩子 | `--line-2` | 中性 | 孩子 |
| 失业 | `--line-2` | 中性 | 失业 |

三条规则：

1. **常态只铺 15% 的一层类型色**，实心色只留外缘 7px 一道弧——和 `GameCard::before` 的顶部色条
   是同一套语言。走过的格子（trail）提到 34%。
2. **只有当前所在的那一格上满色**（92% + 类型色描边），整块棋盘因此只有一个视觉焦点。
3. **12 个机会格不写字。** 24 格里一半是机会，写满就是一堵「机会机会机会」的墙；留白之后
   绿色成了底噪，特殊格自己跳出来——**信息层级正好等于游戏机制的层级**。
   代价是新玩家得点一下才知道绿色是什么。

起点是外环上一枚指向第 1 格的三角 + 「开始」二字。

### 3.2.1 板：留在纸上，不引入实体那块紫

实体棋盘的底是紫的。线上**不照搬**——紫在这套米色界面里是外来户。板底走
`linear-gradient(168deg, var(--panel), var(--panel2))` + `--line-2` 描边，
就是一张暖白卡纸，和三种卡面同一种材质。

留在纸上还多换来一件事：**进快车道换金箔肤时，这块板自己会跟着变金**，
因为它引用的就是会被 `.skin-ft` 覆盖的那两个变量，一行都不用为它另写。
（如果当初选了紫板，这里就得为快车道单独开一套。）

板顶印一枚 `CA$HFLOW` 金色名牌 + 宋体的「老鼠赛跑」/「快车道」，
既是实体棋盘正中那枚 logo，也顺手吃掉竖屏多出来的那条高度。抽屉展开时名牌隐藏。

### 3.3 棋子

- 直径 19px 的圆片，`.avatar-lg` 同款：主色浅底 + 昵称首字。每人一个固定色相（由座位序号定，
  与总览页的头像圈同源，不另发一套色）。位置用**百分比**，跟着板宽一起缩，不为每个档位重算坐标。
- **我的棋子**：多一圈 2px `--brand` 描边，永远画在最上层。
- **同格多子沿半径错开**（一内一外）：格子的径向宽度 40px 比 30px 的弧长更宽，挤得下两个；
  超过 3 个折成 `+N` 徽标，点击展开。
- 走格时棋子沿环形路径逐格跳跃（见 §5.1）。

### 3.4 轮心

轮心只有两样东西：

1. **骰盘**——我的回合是可点的骰子按钮；别人的回合是只读的点数显示（他摇出来的数）
2. **一行状态提示**——「点骰子开始这一回合」/「走了 6 格，停在机会」/「这一格处理完了」

> **轮心不放轮次，也不放目标进度。** 轮次归 HUD 的最后一行（§2.0），
> 目标进度归 HUD 的进度带——两个数都已经在屏幕上了，轮心再写一遍只是把话说两遍。
> 何况轮心在 half 档只有 100px 宽，「第 7 轮 · 阿明行动中」这种长度必然溢出，
> 进度带则会顶到中心圆的边上。**轮心是骰子的位置，别的都让开。**

轮心的字受限于中心圆（可用直径 180px），一律**不用 `white-space: nowrap` 硬撑**——
宁可换行，配 `text-wrap: balance`。

### 3.4.1 骰盘：1 到 3 粒

| 场景 | 粒数 | 每粒尺寸 |
|---|---|---|
| 老鼠赛跑常态 | 1 | 58px |
| 快车道 | 2 | 46px |
| 慈善生效（玩家自选） | 1 / 2 / 3 | 3 粒时 40px |

粒数越多每粒越小——轮心可用直径是固定的，3 粒 40px 加两道 6px 间距共 132px，装得下。

**慈善生效时，粒数选择器替换掉第 3 行的状态提示**，而不是加在它下面：轮心就这么大，
多摞一行就顶到格子上。「慈善生效中 · 还剩 N 轮」写在抽屉的 peek 条里，那儿有横向空间，
主 CTA 也随之变成「🎲 掷 2 粒骰」——按钮说出的就是点下去会发生的事。

说明书语义（design/02）：捐出总收入 10% 之后的若干轮内可自由选择粒数，**每一轮都能重选**，
所以选择器不是一次性的设置，它跟骰子一起常驻到慈善失效为止。

### 3.5 快车道外环

**48 格**（18 绿格 + 23 梦想 + 3 现金流量日 + 慈善/税务审计/离婚/官司），顺序见 design/05 §3.3，
已对实物核实并落进 `fast_track.json` 的 `squares`，`/api/board/fasttrack` 下发。

快车道跟内圈一样是**一条闭合的单圈跑道**，摊成**同一只轮盘**即可。实体棋盘上它画得弯弯曲曲
（底边中间向内绕了一段贴着转盘走），那纯粹是格子太多、长方形盘面排不下的排版手法，
不是两条轨道——走法上没有分叉，第 48 格接回第 1 格。摊成正圆反而更贴近它的本来面目。
入口格（第 1 格「购买一片森林」）放 12 点方向。

轮盘参数：格子多一倍、环收窄一半（外径 140 / 内径 114）——中心因此比内圈更大，
正好摞下两粒骰。呈现规则不依赖具体格数，环按格数自己重新分角：

- 格面不写字，只留色块：绿格 `--deck-small`、梦想粉格 `--deck-dream`、
  现金流量日 `--deck-payday`、四个特殊格中性色；
- **点任意格弹出格子详情**（复用 `FtSquareCard`），这是 24px 的弧读不出内容的补偿；
- 整屏换 `.skin-ft` 金箔皮肤，**棋盘自己跟着走金**（板底就是 `--panel` / `--panel2`）；
- 已被买断的绿格褪成底色（8%）；已被认领的梦想在中径上插一枚该玩家色的圆点；
- 入口是一枚金色三角 + 「在此进入」，对应实体棋盘上那个箭头。

进入快车道的过场屏（`FasttrackIntro`）落幕后直接接上快车道棋盘，帘幕底色与 `.skin-ft` 逐字一致，
这条既有约束保持。

## 4. 回合流：三步

### 4.1 为什么线上的三步和线下不一样

线下三步是「① 银行结算日 → ② 停留格 → ③ 结束」。第 ① 步存在的唯一理由是
**App 不知道你走过哪几格**，只能问你。纯线上服务端知道，所以：

> **纯线上三步 = ① 掷骰 → ② 处理落点 → ③ 结束回合。**
> 经过银行结算日在走格动画里作为一个「过站」节拍自动结算，不占一步，也不再需要
> 「本回合没经过」这个出口按钮。

这是纯线上模式相对线下**唯一的流程简化**，也是它值得做的理由之一——少问一个玩家答不准的问题。

### 4.2 第 ① 步：掷骰

- 中央骰盘是主 CTA，抽屉 peek 档同时给一个全宽 `.btn`「🎲 掷骰子」——手指在屏幕下半部时不用够到中间。
- 慈善生效中先选粒数（默认 1 粒），选择器就在骰盘下方，**不弹层**。
- 骰子由服务端摇（点数写进事件流、可重放、不可重掷）。客户端**不预演**：动画的终值就是服务端返回的值，
  网络慢时骰子持续翻滚直到结果到达，不做本地随机再纠正——那会让玩家看到点数跳变，等于当着面改骰。
- 掷完立即进入走格序列，不需要再点一次「移动」。

### 4.3 第 ② 步：处理落点

落点由服务端派发到既有引擎动作，UI 只负责把「你停在哪」翻译成「你现在要决定什么」：

| 落点 | 抽屉档位 | 内容 |
|---|---|---|
| 机会 | half | 先问「大生意 / 小生意」（两张 `.pill` 大按钮），选完 → 全屏发牌 → 卡面决策 |
| 市场风云 | half | 全屏发牌 → 卡面 + 「已通知 N 位持有该资产的玩家」（既有抽卡人侧文案照搬） |
| 额外支出 | half | 全屏发牌 → 卡面 + 现金 / 信用卡两个支付按钮 |
| 慈善事业 | half | 既有慈善卡片（捐总收入 10%，此后可掷 1–3 粒骰） |
| 孩子 | peek | 直接入账，回执飘出「👶 家里添了一个孩子，每月支出 +$X」 |
| 失业 | half | 既有失业卡片（付总支出、停 2 轮），因为要确认金额 |
| 银行结算日（停在） | peek | 与「经过」同一处理：自动入账 + 回执 |
| 快车道绿格 / 粉格 | half | 既有 `FasttrackPanel` 的格子面板 |

**唯一需要玩家做子选择的落点是机会格**（大 / 小生意）。其余落点都是「发牌 → 决策」或「自动 → 回执」。

### 4.4 第 ③ 步：结束回合

- 抽屉回到 peek，CTA 变成「✅ 结束回合」。
- 落点没处理完（有未结算的强制卡、有待答复的求购）时按钮置灰，副文案写明在等什么——
  沿用线下模式已有的判据，不新增规则。
- 二次确认沿用既有 `endTurn()` 的 `ConfirmDialog`（快车道玩家的文案说「现金流量日」那条也不动）。

### 4.5 进入快车道那一回合

design/02 §9.7 已定案：抽绿卡买资产过线的玩家，`turn_square_used` 已置位，本回合到此为止。
纯线上模式下这条更直观——**棋子已经走过一格，屏幕上看得见**。所以进场引导卡的文案可以从
「本回合到此为止」升级成「你这一步已经走完，下回合从快车道的起点出发」，并在棋盘上把棋子
从内圈移到快车道入口箭头处，做一次 0.6s 的跨轨道飞行。

## 5. 动效

### 5.1 主序列节拍表（掷骰到卡面定格）

| # | 节拍 | 时长 | 说明 |
|---|---|---|---|
| 1 | 骰子翻滚 | 0.5s + 网络等待 | 3D 翻滚，终值 = 服务端点数 |
| 2 | 点数落定 | 0.25s | 骰面放大回弹，`--ease` |
| 3 | 棋子逐格跳跃 | 每格 120ms | 抛物线小跳，格子依次点亮 |
| 4 | **过站结算** | 每次 0.9s | 经过银行结算日：格子脉冲橙光 + 金额飘字 + 回执入栈 |
| 5 | 落点脉冲 | 0.4s | 落点格子外扩两圈同色光环 |
| 6 | 发牌 | 0.5s | 牌背从格子位置飞向屏心并放大 |
| 7 | 翻牌 | 0.45s | Y 轴 3D 翻转，`backface-visibility` |
| 8 | 定格 | 0.6s | 卡面停在屏心，标题扫过一道高光 |
| 9 | 收牌 | 0.4s | 帘幕上移收起，卡片落进抽屉的 half 档 |

单次完整序列约 3.2s（走 6 格、无过站）。**每一拍都能被一次点击跳过**——点击立刻跳到该序列的终态，
不是加速，是终止。玩到第 20 轮的人不该被自己看过 20 遍的动画拖住。

### 5.2 降级与偏好

- `prefers-reduced-motion: reduce`：整条序列压成一次 120ms 淡入，棋子直接出现在落点，
  卡片直接出现在抽屉里，过站结算只留回执。既有 style.css 的 reduce 规则已覆盖大部分，
  棋子位移需要额外写一条（`transition: none`，位置直接跳变）。
- 设置里给一个**「跳过动画」开关**（存 localStorage，不进房间状态），默认关。
- 断线重连后**不补播**任何动效：重连首帧是 `type:'snapshot'`，不带 `lastEvents`，
  这条既有约束正好让棋子直接出现在正确位置，不会把别人五分钟前走的路重演一遍。

### 5.3 全屏发牌翻牌

复用既有 `.curtain` 基座（`--z-curtain`），底色是**该牌堆的颜色降到 12% 叠在纸底上**——
抽的是哪副牌，帘幕就是哪个颜色，玩家在牌翻过来之前就知道自己面对的是机会还是额外支出。

牌背设计：米白卡纸 + 该牌堆色的双线边框 + 中央印牌堆名（宋体，`--font-card`），
和 `GameCard` 的正面是同一套材质，翻过来才对得上。

**全员同步**：其他人的屏幕上同时播放同一段发牌翻牌（说明书要求把卡「大声读出来」，
线上就该人人看见同一张牌翻过来）。差别只在帘幕落下后：抽卡人得到操作区，其他人的抽屉回到 peek
并显示「阿明正在决定」。

## 6. 非我回合：观战

棋盘主视图天生适合观战，这也是选它的理由之一。别人回合时：

- 中央骰盘变成只读点数；他的棋子走格，全员同屏播放同一段动画；
- 抽屉停在 peek，一行写清他走到哪一步：「阿明 · 已掷 5 点 · 正在决定买不买」；
- 抽屉 peek 条右侧给一个头像列，点开是 half 档的牌桌（既有「非我回合的牌桌」那套：头像 + 昵称 +
  他走到回合哪一步 + 现金与月现金流），不新写；
- 房主可代结束回合的按钮，收进 peek 条右侧的 `⋯`，不占主位。

## 7. 边界态

| 情况 | 处理 |
|---|---|
| **断线** | 既有红条「连接断开，正在重连…」照旧；棋盘整体 `.offline-dim`，骰盘禁用并写「重新连上之前，不能掷骰」 |
| **停赛中** | 轮到我时不给骰盘，抽屉 peek 写「停赛中 · 还需跳过 N 轮」+「跳过本回合」按钮 |
| **破产清算** | 抽屉直接 full 档，棋盘只留顶部一线——这时候没有任何理由让人盯着棋盘 |
| **出局** | 棋子变灰并留在原地（看得出谁在哪儿翻的车），抽屉 peek 写「你已出局 · 可以继续观战」 |
| **牌堆见底** | 洗回时在中央信息区飘一行「机会（小生意）· 已洗回牌堆」，1.6s 后消失。不弹层——这是通知，不是待办 |
| **撤销 / 本人更正** | 撤销抽卡后，棋子**不回退**（走格是掷骰的结果，撤的是抽卡不是移动），发出去的牌退回牌堆，全屏发牌序列不重播，抽屉回到落点选择态 |

> 撤销与棋子位置的关系是这一条里最容易做错的：`_revert` 要能把牌退回原位（proposal 已列为风险），
> 但**棋子位置由 `ROLL_DICE` 事件决定**，撤销 `DRAW_CARD` 不该动它。UI 上如果棋子跟着跳回去，
> 玩家会以为骰子也白摇了。

## 8. 视觉：沿用，不新起

本稿**没有引入任何新的颜色、字号、圆角或阴影**。全部取自 `web/src/style.css`：

- 阶段换肤照旧：老鼠赛跑墨绿、快车道 `.skin-ft` 金箔，棋盘跟着变，格子的牌堆色不跟着变；
- 语义色照旧：正绿负红，进账飘字用 `--pos`，扣款用 `--neg`；
- 三种卡面组件（`GameCard` / `ProfessionCard` / `FtSquareCard`）原样复用，发牌序列只是把
  `GameCard` 放进一段动画里，卡面本身一个像素都不改；
- 新增的只有**轮盘、棋子、骰子、牌背**四个物件，它们的材质规则也是既有的那三条：
  纸片底 `--panel`、暖色发丝线 `--line`、`--shadow-sm` 投影。

新增 CSS 类：轮盘本体 `.wheel`（`.plate` / `.disc` / `.wheel-hub` / `.hub`），
其余统一 `.board-*` 前缀（`.board-pawn` / `.board-dice` / `.board-hud` / `.board-stage` /
`.board-tools` / `.board-drawer` / `.board-float`），外加抽屉里的 `.drawer-cta`（钉底按钮条）。
与既有类不冲突。

格子与棋子全部由 SVG 按角度算出来，几何常量（`V` / `R1` / `R0` / `RMID` / `RPAWN`）一处定义，
棋盘渲染与走格动画共用——改半径不会漏掉哪一边。

三个实现上的坑，都在设计稿里踩过一次：

- **悬浮工具挂在棋盘 stage 内部的右上角**。早先它挂在页面根上、靠 `top` 的魔数避开 HUD——
  HUD 一加高就被挡住。之所以能放回 stage 里，是因为档位切换缩的是**棋盘自身的宽度变量**、
  stage 本身不再有 `transform`（见 §2.2）；如果哪天改回缩放 stage，这条也要跟着改回去。
- **`1fr` 的 grid 列默认 `min-width: auto`**，会被 `white-space: nowrap` 的内容撑破容器。
  凡是 grid 里放表格的地方都要写 `minmax(0, 1fr)`。
- **环外的标注（「开始」「在此进入」）容易落到 viewBox 之外**被裁掉半个字。
  外径定下来之后要按 `R1 + 文字半径 ≤ V/2 - 一行字高` 反算一遍。

文字溢出不靠肉眼查：截图脚本跑完会扫一遍 `.screen` 里所有
`scrollWidth > clientWidth` / `scrollHeight > clientHeight` 的元素并列出来
（跳过可滚容器与 SVG 内部）。`line-height: 1` 的大字号标题会误报，给到 1.2 以上即可。

## 9. 埋在这套设计里的取舍（备查）

1. **棋盘做主视图而不是顶部一条**——用户定案。代价是纯线上模式要另写一套页面骨架，
   收益是它看起来像一款游戏而不是一张表格。线下模式因此完全不受影响，反而更干净。
2. **取消 tabbar**——空间冲突下的必然选择。报表/总览/日志收进「账本」，它们本就不是待办。
3. **骰子不本地预演**——宁可等，不可跳变。
4. **动效可一键跳过**——第 20 轮的玩家和第 1 轮的玩家看的是同一段动画，得给出口。
5. **抽屉提档只升不降**——待办不能因为用户随手把抽屉推下去就消失。
6. **棋盘是圆的，不是方格阵列**——照实体来，也照这个游戏的名字来。
   第一版画的是 24 格矩形网格，看过实物才发现丢掉了最认得出的那样东西：
   老鼠赛跑就是仓鼠轮，方格排得再整齐也讲不出这句话。
7. **棋盘留在纸上，不引入实体那块紫板**——紫在米色界面里是外来户；
   留在纸上还白得一件事：快车道换金箔肤时棋盘自己会跟着变。
8. **12 个机会格不写字**——24 格里一半是机会，写满就是一堵墙。
9. **快车道格面不写字**——24px 的弧写不下，改为点开详情。这是格数决定的，不是偷懒。
10. **决策按钮钉在抽屉底**——卡面必须能滚，按钮不能跟着滚走。
