# 系统架构与详细设计

> 版本 v0.1 · 2026-07-18
> 覆盖：技术选型、部署形态、房间/同步模型、数据模型、通信协议、OCR 管线、目录结构。规则语义见 design/02，卡牌数据见 design/04。

## 1. 总体架构

```
┌────────────┐  HTTPS/WSS   ┌──────────────────────────────────────┐
│ 玩家手机浏览器 │◄───────────►│  房间服务器（房主笔记本/树莓派 或 云主机）      │
│  PWA(Vue3)  │              │  FastAPI ── REST(加入/拍照/静态资源)      │
│  ×2..6      │              │          ── WebSocket(状态同步/操作)     │
└────────────┘              │  规则引擎(纯函数) + 事件存储(SQLite)      │
                            │  识别适配层: Cloud / LocalOCR / Manual │
                            └───────────────┬──────────────────────┘
                                            │ 可选外呼
                                     云端多模态/OCR API
```

要点：
- **服务器权威**：一切账目由服务端规则引擎计算；客户端只发"意图"（action），收"状态"。
- **事件溯源**：对局 = 初始状态 + 有序事件日志。持久化事件而非快照，天然获得：断电恢复、全员查账、房主撤销改账（截断+重放）、未来回放复盘。
- **局域网/云端同构**：同一 Docker 镜像；差异仅在 `.env`（监听地址、证书、识别配置）。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI + uvicorn | 与 PaddleOCR 同语言进程内集成最省事；异步 WS 成熟 |
| 规则引擎 | 纯 Python 模块（无 IO） | 便于单测与未来复用到模式二 |
| 存储 | SQLite（WAL） | 单机零运维；一房一库或单库多房均可，取单库 |
| 前端 | Vue3 + Vite + TypeScript + Pinia，PWA | 手机浏览器免安装；PWA 加桌面图标近似 App |
| 通信 | WebSocket(JSON) + 少量 REST | 图片上传走 REST multipart，其余走 WS |
| 本地识别 | PaddleOCR（房主设备已确认为笔记本，性能充足） | 默认引擎 |
| 云识别 | **本期仅预留接口不实现**（无预算）；接口见 §8 | 后期可加多模态 LLM/云 OCR |
| 部署 | **Docker 镜像 + Compose**（已确认交付形态）；局域网 mkcert，云端 Caddy 自动 HTTPS | §7 |

## 3. 数据模型（SQLite）

> 卡牌与棋盘格子数据的**权威来源是 `server/data/` 下的 JSON 文件**（人工可直接修改，见 design/04 §2.5）；下表 card 为启动时从 JSON 导入的运行时缓存，不手工维护。

```sql
-- 卡牌库（由 server/data/*.json 导入的缓存）
card(id TEXT PK, deck TEXT,            -- SMALL_DEAL|BIG_DEAL|MARKET|DOODAD|PROFESSION|FASTTRACK_*
     title TEXT, subtype TEXT,         -- 见 design/04 §2
     data JSON,                        -- 数值字段（结构因 subtype 而异）
     effects JSON,                     -- Effect DSL 指令数组
     ocr_keywords JSON,                -- 匹配用关键词/别名
     image_hash TEXT NULL)

room(id TEXT PK, code TEXT UNIQUE, name TEXT, status TEXT,   -- LOBBY|SETUP|PLAYING|FINISHED
     settings JSON,                    -- 人数上限/是否实体现金/识别模式/快车道现金规则...
     created_at, updated_at)

player(id TEXT PK, room_id FK, seat INT, nickname TEXT,
       token_hash TEXT, is_host BOOL, connected BOOL)

event(id INTEGER PK AUTOINCREMENT,     -- 全局有序
      room_id FK, seq INT,             -- 房间内严格递增
      actor_player_id NULL, type TEXT, payload JSON,
      created_at, revoked_by INT NULL) -- 被撤销时指向修正事件

-- 房间当前状态快照（性能缓存，可随时由 event 重建）
room_state(room_id PK, seq INT, state JSON, updated_at)
```

玩家财务状态（`state JSON` 内，每玩家一份）字段与 design/02 §3.1 一一对应：cash、statement(income/expenses/assets/liabilities)、childCount、charityTurns、skipTurns、phase、dreamId、fasttrack{initialIncome, currentIncome, businesses[]}。

## 4. 通信协议

### 4.1 REST
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/rooms | 创建房间 → {roomCode, hostToken, joinUrl} |
| POST | /api/rooms/{code}/join | {nickname} → {playerToken, playerId} |
| POST | /api/rooms/{code}/recognize | multipart 图片 + {deckHint} → {candidates:[{cardId,title,score}], engine} |
| GET | /api/rooms/{code}/export | 对局事件 JSON 导出 |
| GET | /api/cards?deck=&q= | 卡牌检索（手动选卡） |

### 4.2 WebSocket（/ws?token=）
客户端→服务端统一信封：`{actionId(uuid), type, payload}`；服务端幂等去重（同 actionId 只执行一次）。

**action.type 清单**（与 FR/规则条目对应）：
`SET_TURN_ORDER, SELECT_PROFESSION, START_GAME, END_TURN, PAYDAY, DRAW_CARD(手动选卡: cardId / 确认识别: candidateId), CARD_DECISION(buy/pass/sellOption{toPlayerId,price}/creditCard/…), CORRECT_CARD{eventSeq, correctCardId}(FR-29 入账后更正), STOCK_BUY{qty}, STOCK_SELL{qty}, MARKET_SELL{assetId}, TAKE_LOAN{amount}, REPAY_LOAN{amount}, PAY_OFF_DEBT{liabilityId}, ADD_CHILD, CHARITY, UNEMPLOYMENT, TRANSFER_REQUEST{toPlayerId,amount,reason}, TRANSFER_CONFIRM{transferId,accept}, ENTER_FASTTRACK, FT_PAYDAY, FT_BUY_BUSINESS{squareId}(格子数据取自 board/fast_track.json), FT_BUY_DREAM{squareId}, FT_DOUBLE_DREAM{squareId,targetPlayerId}, FT_CHARITY, FT_TAX_AUDIT, FT_DIVORCE, FT_LAWSUIT, BANKRUPTCY_STEP{...}, HOST_REVERT{eventSeq,reason}, HOST_ADJUST{playerId,delta,reason}`

服务端→客户端：
- `snapshot {seq, state}`：连接/重连时全量；
- `event {seq, event, statePatch}`：增量广播（全房间）；
- `prompt {promptId, targetPlayerId, kind, options, expiresOn}`：需要特定玩家决策的推送（市场卡卖出、转账确认、股票卖出窗口等）；
- `error {actionId, code, message}`。

### 4.3 一致性
- 房间内 `seq` 单调递增，客户端发现跳号即请求 snapshot；
- 所有 prompt 的决策也走 action（带 promptId），过期作废；
- 断线重连：token 恢复 → snapshot + 未决 prompt 重发。

### 4.4 身份找回（FR-4）

会话（房间码 + playerId + 令牌）存在浏览器 localStorage，清缓存/换手机就没了。找回靠
**座位接管**（`POST /api/rooms/{code}/takeover`）：认领已有座位、重发令牌、旧令牌当场作废，
不产生引擎事件（身份是传输层概念，游戏状态不变）。三条约束：

- **任何房间状态都能认领**，不只是 PLAYING。等待阶段丢会话反而更常见（房主建完房还没开局
  就掉线），而那时房间里已经占着他的昵称，重新加入必撞 `NICKNAME_TAKEN`；
  前端捕获这个错误码后直接切到座位列表并预选同名座位。
- **有密码的房间要口令**，无密码房间不设门槛——与「无密码房任何人可加入」同一信任级别。
- 座位列表标注 `online`（`/seats` 与 `/api/rooms` 都给），接管在线座位要二次确认
  （原设备立即掉线）；但**不禁用**在线座位，否则旧设备的僵尸连接会把正当的换设备恢复卡死。

配套地，`DELETE /api/rooms/{code}` 除房主令牌、房间密码外，允许第三条路径：
**无密码 + 未开局 + 当前无人在线**。否则房主一旦丢了令牌，他自己建的无密码空房间
谁都删不掉（没有密码这条路），只能在大厅挂满一整天。设了密码的房间不走这条。

**本机会话绝不能被 UI 顺手清掉**：「连不上对局」的兜底出口只回大厅、不清会话——清了以后
无密码房的房主既进不去也删不掉自己的房间。换身份（建房/加入/接管）时反过来必须**先关旧
WebSocket**：`connect()` 见 `ws` 非空就直接返回，留着旧连接会让新会话永远连不上，
且旧房间的广播还会把「你已不在该房间」判定触发掉，把刚建好的房间变成孤儿。

## 6. 事件溯源与改账

- `apply(state, event) -> state` 纯函数；`validate(state, action) -> event|error`。
- 房主撤销 seq=N：标记 revoked，重放 `events[0..)` 时跳过 revoked 事件重建状态并广播 snapshot。撤销自身也是事件（HOST_REVERT），审计可见。
- 崩溃恢复：启动时对每个 PLAYING 房间重放事件生成 room_state。

## 7. 部署

### 7.1 局域网（默认，✅房主设备=笔记本）
- 交付物 = 单个 Docker 镜像（server 内嵌前端静态资源与 PaddleOCR 模型，离线可用）+ compose 文件；房主笔记本 `docker compose up` 一键启动；
- 首次启动生成 mkcert 根证书与站点证书；玩家扫码页引导一次性信任（或直接用 HTTP + file-capture 拍照方案，零配置）；
- 二维码内容 = `https://<LAN IP>:8443/#/join/<code>`；服务发现不做 mDNS（兼容性差），直接 IP。

**邀请二维码与分享（FR-1，已实现）**：房间页「邀请好友」弹窗（`web/src/components/InviteDialog.vue`）
里展示二维码 + 房间码 + 加入链接。二维码用 `uqr` 算矩阵、自绘内联 SVG（`components/QrCode.vue`），
不发外部请求、非安全上下文照样能画。分享逻辑在 `web/src/share.ts`，降级链：

1. `navigator.share`（Web Share API）调起系统分享面板 → 面板里选微信/QQ 发链接+文案；
   用户取消是 `AbortError`，不当失败处理；
2. 面板不可用（**局域网 http 是非安全上下文，`navigator.share` 与 `navigator.clipboard` 都不存在**）
   → `navigator.clipboard` → 隐藏 input + `execCommand('copy')`；
3. 都不行 → 长按链接手动复制，或直接扫二维码。

微信内置浏览器不支持 Web Share API（其 JS-SDK 分享要公众号认证 + 域名备案，本项目不做），
检测到微信 UA 时只给「复制链接去粘贴」。地址是 `localhost`/`127.0.0.1` 时弹窗会红字警告
「别人扫了打不开，请改用局域网 IP」——房主在自己电脑上开页面时最容易踩这个坑。

### 7.2 云端
- 同一镜像；Caddy 反代自动 Let's Encrypt；域名/IP 写入 `.env`；
- 多房间并存，房间 24h 无活动自动归档（`RoomManager.archive_idle`，事件流保留可查）；
- **从未开局（LOBBY/SETUP）又无人在线的空房 1h 直接删**。这类多半是「建了没连上」的
  空壳，没有值得留存的事件流，归档只会让它们在大厅和库里堆着。

## 8. 识别适配层

```python
class CardRecognizer(Protocol):
    async def recognize(self, image: bytes, deck_hint: Deck | None) -> list[Candidate]
    # Candidate = {card_id, score, engine}

实现（本期）：
- LocalOCRRecognizer   PaddleOCR 提取文本 → 与卡库 ocr_keywords 做
                       加权模糊匹配（RapidFuzz token_set_ratio + 数字特征加分）
- ManualRecognizer     直接返回空候选 → 前端转手动检索
预留（后期，无预算暂不实现）：
- CloudLLMRecognizer   多模态 API：prompt 内嵌该 deck 卡牌标题清单，要求返回 top3 卡名
默认降级链：Local → Manual；超时/低置信自动下一级；全程记录 engine/耗时/结果用于 FR-28 统计。
识别错误修正（FR-29）：确认前可改选/手动检索；确认后走 HOST_REVERT 或本人 CORRECT_CARD
action（撤销原入账事件并以正确卡重放），日志保留修正痕迹。
```

匹配而非解析的关键设计：OCR 只需命中卡面**任意几个稳定词**（标题、代码、独特数字如 $17,000），即可在 ≤300 张的封闭集内唯一定位。竖排/污损容忍度高。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| iOS Safari 对 PWA/WS 后台断连 | 心跳+自动重连+快照拉齐（§4.3）；关键提示用页面内红点而非推送 |
| 局域网证书信任门槛 | 默认走 file-capture 方案，HTTPS 为可选增强 |
| OCR 全挂 | 手动选卡兜底是 P0 主路径（M1 先行） |
| 双轨账目（若保留实体现金） | 房间设置强约束 + 手工调账入口 + 日志审计 |
| 树莓派跑 PaddleOCR 慢 | 换 RapidOCR(onnx)；或该房间直接配云识别/手动 |
| 规则实现错误 | design/02 全量用例 + 属性测试为合入门槛 |
```
