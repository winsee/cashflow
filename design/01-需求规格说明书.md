# 现金流游戏辅助工具 — 需求规格说明书

> 版本 v0.1 · 2026-07-18
> 依据：docs/现金流游戏说明书.pdf（16页）、docs/记录卡.pdf（正反面）、5 类卡片示例图、游戏棋盘图，以及前期口头讨论。

## 1. 项目背景与目标

把纸质版《富爸爸现金流》桌游做成**线上辅助工具**，分两种形态：

- **模式一（当前重点）：线上线下结合。** 实体棋盘、骰子、卡牌照常线下玩；每人一部手机（纯网页，不装 App）作为个人客户端，负责卡牌识别、自动记账、全员状态同步。
- **模式二（暂缓）：纯线上版。** 完整虚拟棋盘/卡牌/走格子，支持异地对战。本期只要求架构上不堵死这条路（规则引擎、卡牌数据库、房间模型均可复用），不做实现。

核心价值：游戏中最繁琐、最容易出错的环节是**手工填写记录卡（损益表/资产负债表）和银行结算**。工具的首要目标是把这部分完全自动化、可审计，从而缩短游戏时长、消除算错账。

## 2. 对前期讨论的修正意见（重要）

前期讨论中有以下几点经评估后认为**不合理或有遗漏**，本文档按修正后的方案编写：

### 2.1 OCR 不应该"逐字段解析卡面"，应该改为"识别是哪张卡"
卡牌是**有限固定集合**（每叠几十张，全套约 300 张以内），且同一张卡的数值永远不变。逐字段 OCR 解析（成本/首期/贷款/现金流…）任何一个数字错了都会导致账目错误，且卡面竖排、字段格式多变（见示例图），解析可靠性差。

**修正方案：** 预先把全套卡牌录成**卡牌数据库**（一次性工作，提供半自动录入工具）。游戏时拍照只需**匹配出是哪张卡**（用 OCR 文本做模糊匹配即可，抗错性极强），数值一律从数据库取。同时提供"手动从列表选卡"作为完整兜底——这意味着 **OCR 彻底降级为可选加速手段，即使识别全挂游戏也照玩**。

### 2.2 "在线/离线 OCR"的离线端跑在哪里必须明确
纯网页端**浏览器里跑不了 PaddleOCR**（Python 引擎）。"离线模式"实际含义应为：**房间服务器（房主的笔记本/树莓派）本地跑 OCR 服务**，对玩家手机而言仍是发 HTTP 请求。可插拔接口做在服务端：云端多模态 API / 服务器本地 PaddleOCR / 手动选卡，三者同接口、可配置、可 fallback。

### 2.3 浏览器摄像头在局域网 HTTP 下会被禁用
`getUserMedia`（网页调摄像头实时取景）要求 HTTPS 或 localhost。局域网用 `http://192.168.x.x` 访问时**拍照功能会直接不可用**。方案（详见架构文档 §7）：
1. 首选 `<input type="file" capture="environment">`（调系统相机，不受安全上下文限制）；
2. 需要实时取景时，房间服务器用 mkcert 自签证书 + 扫码信任引导，或云端部署用正式证书。

### 2.4 "全自动记账"与"实体现金照发"会双轨脱节 ✅已决策
**已确认（2026-07-18）：取消实体纸币和纸质记录卡**。App 就是银行 + 记录卡（骰子、棋盘、实体卡牌照旧）。玩家现金余额由系统权威记录，统一显示在电子记录卡的**"银行储蓄"**栏（开局值 = 月现金流 + 储蓄，之后所有收支都进出该栏）；银行结算日、支出、买卖全部走系统。

### 2.5 "玩家间交易暂不做"与游戏规则冲突
规则里**玩家间资金流是刚性存在的**：机会卡可转卖给其他玩家（价格双方议定）、市场风云卡触发全员卖资产、快车道上梦想被别人买走要加价。如果记账要闭环，这些资金流必须能录入系统。修正为：不做复杂的挂单/谈判系统，但**必须做"简单转账/交易确认"**（A 发起 → B 确认 → 系统过账），覆盖上述场景。

### 2.6 人数上限
官方玩法支持 2–6 人（说明书建议"找 1~5 个朋友"）。房间人数做成**可配置 2–6**，不写死 5。

### 2.7 需要轻量回合指针
慈善（3 轮内可用 2 粒骰子）、失业（停赛 2 轮）、破产（停赛 3 轮）、机会卡失效（"下一玩家前进时失效"）都依赖回合计数。服务器看不见实体骰子，因此需要**极轻量的回合跟踪**：当前玩家在自己手机点"结束回合"。这不是负担——它同时是"该谁了"的提醒，也是回合类状态自动倒计时的依据。

### 2.8 审计师角色自然消失
说明书中"审计师"（右手边玩家帮你核账）在数字化后由系统自动校验取代，不需要线上化，但对局日志要能让所有人查账（等价于审计）。

## 3. 用户与角色

| 角色 | 说明 | 权限 |
|---|---|---|
| 房主 | 创建房间的人，通常也是玩家 | 房间设置、开始/结束游戏、裁决性改账（撤销/修正）、移除玩家 |
| 玩家 | 每人一部手机 | 操作自己的财务：拍卡/选卡、买卖、借还款、结算、结束回合；查看全员总览 |
| 观战者（可选,低优先） | 扫码进入只读 | 仅查看总览 |

无注册体系：昵称 + 房间口令进入，浏览器存重连令牌。

## 4. 功能需求（FR）

优先级：P0 = MVP 必须；P1 = 第一个可玩版本后尽快；P2 = 待定/后续。

### 4.1 房间与连接
- **FR-1 (P0)** 创建房间：生成房间码 + 二维码（含服务器地址）；支持扫码或手动输入地址+房间码加入。
- **FR-2 (P0)** 房间容量 2–6 人可配置；断线重连（令牌恢复身份和状态）。
- **FR-3 (P0)** 服务器可部署于局域网设备或云主机，代码一致，仅配置不同。
- **FR-4 (P1)** 对局中途换设备恢复（凭房主批准）。

### 4.2 开局
- **FR-5 (P0)** 玩家抽实体职业卡后，在手机上从职业列表中选择（或拍照识别）自己的职业；系统自动生成初始损益表/资产负债表。
- **FR-6 (P0)** 系统自动执行开局发钱：初始现金 = 月现金流 + 储蓄，并自动注销储蓄（规则见规则引擎规格 §4）。
- **FR-7 (P0)** 掷骰定先后在线下完成；房主在系统里按结果排定回合顺序。

### 4.3 回合与卡牌流程（老鼠赛跑）
- **FR-8 (P0)** 当前玩家结束回合按钮；系统维护回合指针与回合数，自动倒计时慈善/停赛等回合状态。
- **FR-9 (P0)** 抽卡录入：拍照识别（云/本地 OCR 可配置，返回候选卡）→ 玩家确认；或直接手动检索选卡。错误率目标：确认后入账错误 = 0（因为数值来自卡库）。
- **FR-10 (P0)** 按卡牌类型自动弹出操作选项并入账（完整效果清单见规则引擎规格 §6）：
  - 机会-房地产/企业：买 / 不买 / 转卖给其他玩家（转卖走交易确认流程）；
  - 机会-股票：按今日价格买入 N 股；同时向全员广播，允许其他玩家按卡面规则卖出持仓；
  - 机会-事件（如承租人损坏财产）：自动结算强制支出；
  - 市场风云：向**所有持有相关资产的玩家**推送"按价出售？"选项，逐一确认并过账；经济事件（如通胀收房）强制执行；
  - 额外支出：强制扣款；可选信用卡支付的卡按卡面生成负债+月支出；现金不足时引导银行贷款。
- **FR-11 (P0)** 银行结算日：玩家点"结算"（或结束回合时系统提示"本轮是否经过了银行结算日"），自动收付月现金流。
- **FR-12 (P0)** 棋盘事件录入：孩子（+1，上限 3，自动加孩子支出）、慈善（扣总收入 10%，标记 3 轮双骰）、失业（付总支出，停赛 2 轮，清除慈善状态）。
- **FR-13 (P0)** 银行贷款/还款：借款千元倍数、月息 10% 自动入账；还款按千元递减利息；每轮可清偿其他负债（校验"须一次性还清"及不可清偿项）。
- **FR-14 (P0)** 破产流程半自动引导：按规则折价卖资产、清偿、判定出局或停赛 3 轮（规则引擎规格 §8）。
- **FR-15 (P0)** 玩家间交易确认流程：发起（对象、金额、备注/关联卡）→ 对方确认 → 双方过账，全部入日志。

### 4.4 快车道
- **FR-16 (P0)** 系统自动检测"非工资收入 > 总支出"，提示可进入快车道；确认后自动换算：财产 = 非工资收入（按千元四舍五入）×100，生成快车道面板（现金流量日收入、胜利目标 = 初始 + $50,000）。
- **FR-17 (P0)** 快车道操作：现金流量日收款；购买企业投资（记录格子/名称，累计现金流增量，检测 +$50,000 胜利）；购买梦想（含"别人踩了我的梦想加价 100%"的成本追踪）；税务审计/离婚/官司（半额/全额/半额扣现金）；慈善（1-3 粒骰）。
- **FR-18 (P0)** 胜利判定与结算画面（两种胜利条件）。

### 4.5 信息展示
- **FR-19 (P0)** 个人面板 = 电子记录卡：损益表、资产负债表、现金余额、回合状态，实时计算总收入/总支出/月现金流/非工资收入。
- **FR-20 (P0)** 总览 Tab：全员现金、月现金流、非工资收入/总支出进度（离跳出老鼠圈还差多少）、资产列表、回合指针。
- **FR-21 (P0)** 对局日志：每笔账可追溯（谁、何时、哪张卡、金额、前后余额）。
- **FR-22 (P1)** 房主改账：对任意一笔历史操作撤销/修正，全员可见修正记录。

### 4.6 卡牌数据库
- **FR-23 (P0)** 内置卡牌库 schema 与种子数据（本期已从示例图录入 10 张，见卡牌文档 §5）。
- **FR-24 (P0)** 录入工具：逐张拍照 → OCR 预填 → 人工校对入库。全套约 200–300 张，一次性完成。
- **FR-25 (P1)** 卡库导入导出（JSON），便于分享/备份。

### 4.7 识别（OCR/匹配）
- **FR-26 (P0)** 识别接口可插拔：`LocalRecognizer`（服务器本地 PaddleOCR）、`ManualPick`（无识别）本期实现；`CloudRecognizer`（云端多模态/OCR API）仅定义接口预留（见 FR-30）。房间级配置 + 失败自动降级链，本期默认：本地→手动。
- **FR-27 (P0)** 识别输出为**候选卡列表（Top-3）+置信度**，玩家确认后才生效；识别与入账解耦。
- **FR-28 (P1)** 识别效果统计（命中率、耗时、费用计数），用于云/本地对比。
- **FR-29 (P0)** 识别错误的手动修正：确认前可在候选列表外改为手动检索选卡；确认入账后发现选错卡，可发起"更正"（撤销该笔并重新选卡入账，走事件撤销重放，全程留痕）；卡库本身数值有误时可在录入工具中修正（对局外生效）。
- **FR-30 (P0)** 云识别本期只预留接口不实现（无预算）；默认识别链 = 服务器本地 OCR → 手动选卡。

### 4.8 辅助功能
- **FR-31 (P0)** App 内提供**游戏说明书查看入口**（内置 docs/ 说明书扫描页，可翻页/缩放，离线可用），并在相关操作旁提供对应页码的快捷跳转（如破产流程 → 第5页）。

## 5. 非功能需求（NFR）

- **NFR-1** 平台：手机浏览器（iOS Safari ≥16、Android Chrome ≥110）；桌面浏览器用于房主/大屏总览。纯 Web，无安装。
- **NFR-2** 规模：单房 ≤6 人；服务器单机支撑 ≥10 并发房间（为云端多桌预留）。
- **NFR-3** 延迟：局域网内状态同步 <500ms；操作确认 <1s（不含 OCR）。OCR：云 <5s，本地 <8s，超时自动降级。
- **NFR-4** 可靠性：服务器崩溃/断电后可从持久化的事件日志完整恢复对局；手机锁屏/切后台回来自动重连并拉齐状态。
- **NFR-5** 正确性：所有账目由服务器端规则引擎计算，客户端不做权威计算；每笔变更可审计、可回放。**规则引擎须有全量单元测试覆盖（含说明书示例数值的回归用例）。**
- **NFR-6** 安全：房间口令 + 会话令牌；不采集个人信息；云 OCR 仅上传卡面照片。
- **NFR-7** 成本：本地模式零边际成本；云 OCR 按次计费可设房间限额。
- **NFR-8** 版权：卡牌数据库仅存储游戏数值与简短标题（玩家对照实体卡阅读完整文案），不复制整段卡面文案与美术素材；工具仅供已拥有正版实体游戏的玩家私人使用，不做公开分发运营。

## 6. 范围外（本期不做）

- 模式二纯线上棋盘（架构预留）；
- 语音/视频、聊天；
- 账号体系、排行榜、战绩云存档；
- 卡牌议价撮合（转卖价格线下谈好后录入即可）；
- 多语言。

## 7. 里程碑建议

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0 | 卡牌库 schema + 录入工具 + 全套卡牌数字化 | 卡库完整，抽检无数值错误 |
| M1 | 房间/开局/回合/手动选卡 + 全部老鼠赛跑记账 + 总览 + 日志 | **不用 OCR 能完整玩完一局老鼠赛跑** |
| M2 | 快车道 + 破产 + 交易确认 + 改账 | 完整对局跑通，两种胜利均可达成 |
| M3 | OCR 接入（本地 PaddleOCR + 降级链，云接口仅预留）+ 识别统计 | 实拍命中率 ≥95%（Top-3 含正确卡） |
| M4 | 云部署方案、HTTPS、多房间 | 异地房主可开房 |
| M5(待定) | 模式二纯线上 | — |

> M1 先于 OCR：可玩性与账目正确性是根，识别只是输入加速。

## 8. 开放问题决议记录（2026-07-18 已全部确认）

1. **实体现金取消**：App 即银行，玩家现金记录于电子记录卡"银行储蓄"栏（§2.4）。
2. 房主设备 = **笔记本**；交付形态为 **Docker 镜像**（compose 一键启动，见架构文档 §7）。
3. 云端识别**暂无预算**：本期只预留可插拔接口，不实现云引擎；默认 本地 OCR → 手动。
4. 卡牌总数未清点：以录入工具实录为准，录入完成后的清单即权威清单。
5. 快车道现金处理：**一切按说明书**——进入快车道时老鼠赛跑阶段现金交回银行。
6. 游戏时长控制：**不做**。
7. 新增需求：App 内提供**说明书查看入口**（FR-31）。
