# 卡牌数据模型与识别方案

> 版本 v0.2 · 2026-07-21
> 卡牌库是账目正确性的根：游戏时数值一律取自卡库，识别只负责"定位是哪张卡"。
>
> ⚠️ **本文档部分内容已被 [06-卡牌数字化结果与设计修订.md](06-卡牌数字化结果与设计修订.md) 修订**，冲突处以 06 为准：
> 1. 原"卡库只存数值、不存整段卡面文案"的约束**已作废** —— 卡面原文逐字存入 `raw` 字段（纯线上版要靠它渲染卡面）；
> 2. §2 的 subtype 体系由 13 个扩到 18 个；求购卡新增计价基准、股票卡新增买家范围等字段（见 06 §3）；
> 3. §5 的 14 条种子数据已被全套 194 张实录数据取代。

## 1. 总体思路

1. **一次性数字化**：用录入工具把用户这套实体牌逐张拍照→OCR 预填→人工校对→入库（约 200–300 张，预计 2–3 小时）。
2. **游戏时识别 = 封闭集匹配**：拍照 → 提取文本/视觉特征 → 在对应牌叠内模糊匹配 → Top-3 候选 → 玩家确认。
3. **手动选卡永远可用**：按牌叠 + 关键字检索列表。

## 2. 卡牌类型体系（deck × subtype）

| deck | subtype | 说明 |
|---|---|---|
| SMALL_DEAL 小生意 | REALESTATE | 房地产（≤$5,000 首付类交易） |
|  | STOCK_OFFER | 股票/基金报价（抽卡人可买，人人可卖） |
|  | STOCK_EVENT | 拆股/并股等持仓事件 |
|  | LOSS_EVENT | 持有资产者的损失事件（如承租人损坏财产付 $500） |
| BIG_DEAL 大买卖 | REALESTATE | 房地产（≥$6,000 交易） |
|  | BUSINESS | 企业投资 |
|  | EXPENSE_EVENT | 资产持有者维修/支出事件（如下水管破裂每套 8 室楼付 $2,000） |
| MARKET 市场风云 | BUYER_OFFER | 定价求购某类资产（人人可卖） |
|  | MULTIPLE_OFFER | 按原价倍数收购（如有限合伙 3×） |
|  | ECONOMY_EVENT | 强制/修饰性经济事件（如通胀收走 3室2厅） |
| DOODAD 额外支出 | CASH | 纯现金支出（可带条件如"有孩子才付"） |
|  | CREDIT_OPTION | 可选信用卡支付（负债+N，月支出+m） |
|  | INSTALLMENT | 首付 + 新负债 + 新月供 |
| PROFESSION 职业 | — | 初始报表全套数值 |

## 2.5 存储格式：JSON 文件为权威数据源（人工可改）

卡牌与棋盘格子数据一律以**结构化 JSON 文件**保存并纳入 git 版本管理，SQLite 中的 card 表只是启动时导入的运行时缓存——**人工修正/补充直接改 JSON 文件**（或通过录入工具改，工具的保存动作就是写回 JSON）：

```
server/data/
├─ cards/
│  ├─ small_deal.json      # 小生意
│  ├─ big_deal.json        # 大买卖
│  ├─ market.json          # 市场风云
│  ├─ doodad.json          # 额外支出
│  └─ professions.json     # 职业卡
├─ board/
│  ├─ rat_race.json        # 内圈24格序列
│  └─ fast_track.json      # 快车道全部格子（design/05 的数据）
└─ schema/                  # 各文件的 JSON Schema，用于校验
```

约定：
- 文件内为对象数组，字段见 §3；UTF-8、缩进 2 空格、金额为整数（不带千分位/货币符），便于 diff 与手改；
- 服务启动时校验（JSON Schema + 业务校验如 cost=downPayment+mortgage）后导入 SQLite；校验失败启动报错并指出行号；
- 提供 `--reload-data` 命令/管理接口在不重启对局服务的情况下重新导入（进行中的对局不受影响，新对局用新数据）；
- 录入工具（§6）的输出就是这些 JSON 文件，人工改动与工具录入完全等价。

## 3. 数据 Schema 与 Effect DSL

```jsonc
// card.data —— 按 subtype 取对应形状（TypeScript 风格示意）
REALESTATE: { assetType: "3室2厅"|"2室1厅"|"4室公寓"|"8室公寓"|..., 
              cost, downPayment, mortgage, cashflow,
              roiPct?, priceRange?: [lo, hi] }
STOCK_OFFER: { symbol: "ON2U"|"OK4U"|"MYT4U"|"GRO4US"|..., price,
               priceRange: [lo, hi], dividendPerShare: 0 }
STOCK_EVENT: { symbol, ratio: "2:1"|"1:2" }          // 并股/拆股
LOSS_EVENT:  { condition: "hasRentalProperty", amount: 500 }
EXPENSE_EVENT:{ targetAssetType: "8室公寓", amountPerUnit: 2000 }
BUYER_OFFER: { targetAssetType: "2室1厅", pricePerUnit: 55000 }
MULTIPLE_OFFER:{ targetAssetType: "有限合伙", multiple: 3 }
ECONOMY_EVENT:{ kind: "FORCED_SURRENDER", targetAssetType: "3室2厅" } // 等
CASH:        { amount: 2000, condition?: "hasChildren" }
CREDIT_OPTION:{ amount: 4000, creditMonthly: 120 }
INSTALLMENT: { downPayment: 1000, liability: 17000, liabilityName: "游艇信贷",
               monthly: 340 }
PROFESSION:  { salary, taxes, mortgagePayment, schoolLoanPayment, carLoanPayment,
               creditCardPayment, otherExpenses, extraExpenses, perChildExpense,
               savings, liabilities: { mortgage, schoolLoan, carLoan, creditCard, extra } }

// card.effects —— 引擎执行指令（由 subtype 模板生成，特殊卡可覆写）
[{ "op": "OFFER_BUY_ASSET" }, { "op": "BROADCAST_SELL_WINDOW" }, ...]
// op 全集：OFFER_BUY_ASSET / OFFER_RESELL / STOCK_TRADE_WINDOW / ADJUST_SHARES
//         / FORCE_PAY / OPTIONAL_CREDIT / ADD_INSTALLMENT / MARKET_SELL_OFFER
//         / FORCED_SURRENDER / APPLY_PROFESSION
// 语义与规则引擎规格 design/02 §6 一一对应
```

`ocr_keywords`：标题词 + 代码 + 显著金额（如 "17,000"、"ON2U"、"下水管"），用于匹配打分。

## 4. 识别管线细节

```
照片 → 预处理(自动旋转/透视矫正可选)
     → 本地OCR(PaddleOCR)：全文识别 → RapidFuzz 对 ocr_keywords 加权评分
         评分 = 0.6×标题相似度 + 0.3×显著数字命中 + 0.1×代码命中
     → 置信度 <0.55 或超时 → 转手动检索
     → 前端展示 Top-3（含卡名+关键数值摘要）→ 玩家确认 → 入账
（云多模态引擎为预留扩展位，本期不实现；接入后置于本地引擎之前即可）
```

**识别错误修正（FR-29）**：确认前——候选不对可直接切手动检索；确认后——本人或房主发起
"更正"，撤销该笔入账并以正确卡重放，日志留痕。卡库数值本身录错：在录入工具改库，
仅影响之后的对局（进行中对局如需修正走房主调账）。

- deck_hint 必传（玩家先点了"抽小生意/大买卖/市场风云/额外支出"），把搜索空间缩到单叠几十张。
- 同名不同数值的卡（同标题多版本）靠显著数字区分；录入时若发现重复标题必须补充区分关键词。

## 6. 录入工具（M0）

- 网页工具（复用主前端框架）：选 deck → 连拍 → 每张跑本地 OCR 预填字段 → 人工逐项校对 → 保存；
- 强校验：REALESTATE 必满足 `cost = downPayment + mortgage`（不满足需人工二次确认）；金额千分位/全半角清洗；重复标题告警；
- 进度统计：各叠已录张数 vs 用户清点的实体张数（开局前对账）。

## 7. 验收

- 全套卡录入后抽样 30 张与实体逐字段核对，错误 0；
- 实拍识别测试集（不同光线/角度 ≥60 张照片）：Top-3 命中 ≥95%，Top-1 ≥85%；
- 云/本地引擎分别出报告（FR-28）。
